# Design System: Corral corral-pi workbench

## Overview

**Creative North Star: "The panel workbench"**

A real native coding session stays primary. One graphite canvas, thin rules, rounded boxes and restrained blue focus make related state accessible without replacing Pi's transcript, editor or authorization lifecycle.

**Key Characteristics:**
- Native character-cell panels, not a web dashboard.
- Persistent context beside the conversation and a boxed composer under it.
- Shared keyboard/pointer inspection without a second conversation runtime.
- The same frame in every role (worker, reviewer, assistant, build).

## Colors

The normative palette above is the dark appearance of `PACKAGED` in appearance.ts; the light and contrast appearances keep the same roles. panels-view.ts exports each role as a live binding that `setPanelAppearance` updates (`PANEL_BG`, `PANEL_TEXT`, `PANEL_MUTED`, `PANEL_BLUE` for accent, `PANEL_RULE`, `PANEL_LINE`, `PANEL_SELECTED`, `PANEL_RAISED`, `PANEL_KEY`, `PANEL_DIALOG`, `PANEL_BUBBLE`, `PANEL_HEAD`, `PANEL_CODE`, `PANEL_ON_ACCENT`, `PANEL_SUCCESS`, `PANEL_WARNING`, `PANEL_ERROR`); panel-canvas.ts paints the background as the alternate screen's default cell colour, and panels-theme.ts maps the same palette onto Pi's theme.

- **background** is the one surface of the whole screen: header, tabs, every view, the sidebar, the composer, status bar and footer.
- **raised** is a card's header row, a popup and the toast; **dialog** the header row of a docked dialog and a diff's hunk rows; **bubble** a user message and the prompt of an agent's conversation; **selected** a selected row and a count chip; **key** a key cap. The active tab's key cap and the role pill are **accent** with **on-accent** bold text. Diff rows sit on their own added and removed surfaces. Nothing else fills a background: no bands, no panel fills, no lighter rail.
- **line** draws borders, rules and separators; **rule** the borders of popups and the toast, the timeline's waiting dashes and the scrollbar thumb; **head** bold headings in details and popups (`Timeline`, `Commands`, the F1 group titles) and Markdown headings; **code** inline code and code blocks.
- **accent** marks focus, selection bars, links, tool names and clickable labels. Success, warning and error always keep a word or glyph beside the colour.

Pi's syntax and Markdown tokens are set to text, except links, code, headings, tool titles and diff additions and removals. Agents carry one of eight hues per appearance (appearance.ts `AGENT_HUES`, at least 4.5:1 on the background and selected surfaces); a hue identifies an agent across the table, timeline, sidebar, Changes and the conversation header and never encodes state.

**The State Rule.** Displaying progress, a tool result or a diff does not imply a passing gate, review or owner acceptance.

## Typography

The terminal owns font, size, cell dimensions and shaping. No application font is installed or forced. Color, weight, spacing and literal state labels form the hierarchy. Wide glyphs are measured before clipping; controls in data are sanitized.

## Layout

The screen stacks, top to bottom: the header rows, the tab row, a rule, the body, the dock (a docked build dialog, then the owner questions, then the queue, then, without a rail and without a dialog, the collapsed sidebar row or its drawer under its own rule), the composer box, the status bar, a rule and the footer row. Every one of these spans the full terminal width. From 105 physical columns the body holds the main view and the sidebar rail: 34 columns (24–40, the main view keeps 70) with a `│` column in the line colour on its left, filling exactly the rows between the tab rule and the dock. Below that, or after the sidebar key hid the rail, the sidebar is the collapsed row, which opens into a drawer of `rows − 12` body rows, clamped to 2–10 (at most 5 below 28 rows). Width tiers by physical columns: wide 150+, mid 105–149, narrow 64–104, tiny below 64. Short is below 28 rows, very short below 20: header row 2 hides, the composer bar folds away (the status bar then carries the model and effort), and the queue dock, drawer and stacked Changes list shrink. Below 16 rows the rules go first: under the tabs, above the footer and above the collapsed row. Pi's `Working` loader row is hidden; the working indicator in the composer's top border takes its place (see Working indicator). Pi owns transcript scrolling/follow, selections and editor height. Panel content scrolls or pages independently; SDK overlays own modal input.

**The Continuity Rule.** Resize, relocation and inspection preserve draft, open view, sidebar tab and selection, and the bound session.

**The Focus Rule.** One surface has the keys at a time (`PanelFocus`: the composer, the main view, the sidebar, the queue, the owner questions or a docked dialog), and only that surface looks focused. Every role starts on Chat with the keys in the composer. With the keys the composer has an accent border, an accent `›` and the cursor; without them the border is in the line colour, the `›` muted and no cursor cell is drawn, so the one cursor on screen is where the next key goes. A view opened by its key, its tab or a click takes the keys: its tab cap is the active accent cap and its selection bar accent; once the keys leave, the cap turns muted on the key surface and the bar muted. Tab gives the keys back to the composer; so do `/` (always a command) and any letter the view does not offer right now, which is typed there. A bracketed paste is always typing: whatever has the keys, the pasted text goes to the composer and the composer takes the keys. Enter in a view without an Enter action does nothing. Each main tab opens with its F-key and with Alt+1 to Alt+5 in tab order (through Alt+4 without a bound task), each Alt key only while the user left it free (`freeKey`). Esc goes one step back and reaches Pi's interrupt only from Chat with the composer focused; an Esc within 600 ms of an Esc that navigated is ignored (`EscGuard`), so pressing Esc to get out never also stops the turn, and landing in Chat while a turn runs says `Back in Chat · esc again stops the turn`.

**The Key Cap Rule.** A key is shown as a key cap (`keyCap`), and a cap that is drawn is clickable and does what its key does. Caps appear on the tab row, in the footer, beside the sidebar toggle (the sidebar key: `Ctrl+B`, or `Alt+B` when the session runs in herdr and Ctrl+B is herdr's prefix; every cap draws the chosen key), in front of the actions of a selected agent, job or board task, on the queue row's edit control, on the F2 palette rows and in the F1 list (including its `esc close`). An action that cannot run now shows its muted label without a cap. The composer, the status bar, cards, the docked dialog's options and the conversation carry none. The footer always lists the keys of whatever has the focus, whether or not the view shows them too.

## Elevation & Depth

One background everywhere. Depth comes from one-cell rules and rounded borders in the line colour, the raised header rows of cards, raised popups and toasts, and the selected surface. The alternate-screen adapter supplies default foreground/background through SGR, not terminal-palette/default-color setters; the surrounding terminal and normal screen retain their theme. Read-only details and existing prompts are corral-pi overlays/selectors, not extra browser windows.

## Shapes

Rounded boxes (`╭ ╮ ╰ ╯ │ ─`) with one blank cell of padding inside their sides: cards, titled boxes, the composer, popups, the toast and the docked dialog. A horizontal border between regions is one row of `─`; a vertical one (left of the rail, between the Changes file column and the diff) is its own column of `│` on every row. Every view sits one cell in from the main area's left edge with one blank cell on the right, where its scroll bar draws; views that draw from their first column (Task, Proof, Events, Usage, Artifacts) are wrapped by `inset` in workbench.ts. The composer keeps the SDK's real editing behavior inside its box.

## Components

### Shared primitives (frame.ts)
Every surface draws with these and does not redefine them; each line is exactly the width it is given and ends on the background.

- `keyCap(key, on?, restore?)`: the key in accent on the key surface with one cell of padding each side. `on` draws the active form (accent surface, on-accent bold), used only for the open tab. `restore` names the surface the row continues on (a cap on a selected row). Use it for every key shown anywhere; header.ts wraps it with a `tight` form without padding.
- `countChip(text)`: text on the selected surface with one cell of padding; tab counts. A warning, error or success count keeps its tone as the signal.
- `spinner(now, phase?)`: the braille frame `⠋⠙⠹⠸⠼⠴⠦⠧` (110 ms each), `phase` staggering rows; a steady `●` while `Motion: still`. It is the running state wherever the agent, a tool call, a job, a slice, a plan step or a board task runs, and it advances only on the shared clock (see Working indicator); the other states keep their glyphs: `○` waiting, `✓` done, `✗` failed or cancelled, `▲` needs you, `!` uncertain.
- `card(header, body, width, { right?, tone?, selected? })`: a rounded card whose first row is the header on the raised surface (`right` right-aligned), then the body rows. `tone: "accent"` draws the border in accent and the header on the dialog surface, for docked dialogs only. `selected` puts a body row or range on the selected surface with the accent bar. Use it for conversation cards (at most 108 cells wide), the job output card and dialogs.
- `titledBox(title, body, width, { tone? })`: a rounded box with the title set into its top border (`╭─ title ──╮`), accent while it has the focus; the legend on the Command page. The composer draws the same shape in composer-chrome.ts.
- `rule(width)`: one row of `─` in the line colour; the tab rule, the footer rule, the rule above the collapsed sidebar row and the dividers inside Agents.
- `popup(title, right, body, width, selected?)`: the raised surface, a rounded border in the rule colour, a title row and a divider in the line colour, then the body with an optional selected row; the F1 keys list and the F2 actions.
- `onSurface(text, surface)`: sends every return to the canvas inside `text` back to `surface`, so a styled span keeps a card header, bubble or selected row on its surface. Use it whenever styled text is composed onto a surface other than the background.

### Header and tabs
Two rows across the full width (one when short). Row 1: `corral / <target>` in bold accent (`<target>` alone when tiny); at the right edge, in a build session, a reversed warning chip for agents that wait for the owner (see Build sessions), then the state word `Working`, `Idle` or `Unavailable` muted, lower case below 105 columns. While a run is active the state word (or the build exit status) carries a mark before it: the spinner in accent, `▲` in warning while the agent waits for the owner, `!` in warning while the model stalls; the word is followed by ` · <turn elapsed>` (not when tiny). A notice takes the state word's place for its time (see Notices and attention). Row 2, muted, shows whenever the terminal has 28 rows or more, at every width, clipped: task id and title with status, priority and size on the right, or project, directory and branch, plus `Changes: <scope>` when Changes reads another scope. Its left part keeps 60% of the row; the right part takes its short form, then clips, and drops below 6 cells. The tab row follows: per main view a key cap and its label (`F5 Task`, `F9 Chat`, `F8 Agents`, `F7 Changes`, `F10 Proof` or `F10 Plan`; Task and Proof only for task-bound roles, Plan otherwise), separated by `│` in the line colour. The open tab has the active key cap while its view has the keys (a muted cap on the key surface otherwise) and a bold label underlined in accent; the others a plain cap and a muted label. A sub-view puts its place on its tab: `Task › Events` (`Chat › Events` without a task), `Proof › Artifacts`, `Chat › Usage`, the tab's own label when tight. The Chat tab carries an accent `•` after its label once a new transcript entry (a message, a tool row or any other entry) arrived behind another view; text streaming into an entry already there does not set it, and it clears when Chat opens. Badges are count chips that say what they are about, never colour alone: a count, `project?` without a project, `git?` after a failed Git read, Proof's gate in words (`gate ✓`, `gate ✗`, `no gate`, then `· approved` or `· changes` and `· stale` where the row has room, `proof?` after a failed read with nothing retained); Chat has none. Fitting is measured in order: long badges shorten, the separators go, `Changes` reads `Diff`, inactive tabs lose their labels (a badge stays on the bare cap, `F7 3`), then badges go one at a time, warnings and errors kept longest; the unread dot never goes. If the row still does not fit, the open tab and its nearest neighbours stay. The tab row hides while an expanded image is open. A rule follows from 16 rows.

### Working indicator
activity.ts observes Pi's extension events and says what the main agent is doing, in every view and every width tier, near the right corner of the composer's top border (before `↑ n more`). It lists variants from the longest to the shortest and the composer draws the longest that fits beside the title, never squeezing `Message → <receiver>`. Phases, highest first:

- `▲ waiting for you` in warning: a blocking dialog the agent opened (the owner's own palette, keys list and pagers do not count).
- `compacting context`; `retrying after an error` in warning, while Pi retries a failed response.
- `running <tool>` while top-level tools run: `running bash`, `running codemode › read` for the latest call a cell made, `running 3 tools` for parallel calls. Tool names read as words (`job wait`).
- The model stream: `waiting for the model` (request sent, no data yet), `thinking`, `writing`, or `writing <tool>` while a tool call's arguments stream.

The spinner leads, then the phase in muted, then the phase's elapsed time (`42s`, `1m 04s`, `1h 02m`; `1m04s` below 64 columns). From 105 columns the row starts with `Working`, from 92 it ends with the stop key (`esc stop`, from the configured interrupt key); shorter variants drop the stop key, then the long phase for a short one (`bash`, `you`), then everything but the spinner and time. With no model data for 60 s while the turn waits on the model, the indicator turns into `! no data from the model for 1m 05s` in warning (shortening to `! no data for …`, `! …`). When the turn settles it shows `✓ done · 3m 12s` or `✗ stopped · 42s` for the notice time (3.2 s); when the owner is not in Chat and the turn ran over 10 s, a notice says `Turn finished · 3m 12s` (or `Turn stopped`) as well. Every state carries a glyph and a word.

**The shared clock.** `ActivityClock` is the one redraw timer: it ticks every 110 ms (every second while `Motion: still`) and requests one redraw per tick, only while a run is active, a compaction runs, the turn-end label shows, or a live row holds it (`Ticker.hold(id)`: a backgrounded job row, a detached Code Mode cell). Otherwise it schedules nothing. Rows never start timers of their own. `Motion: animate | still` is an F2 setting beside Density, session-local like Appearance: still draws the spinner as a steady `●` and slows the clock to one tick a second.

### Notices and attention
Panel feedback (a refusal, `Removed queued input · not sent`, `Steered <id>`, a model change) is a notice for 3.2 s (`NOTICE_MS`). It takes the state word's place in header row 1, in its tone, when it fits there whole beside the short attention chip and the kept title; a longer one is a toast at the top right of the main view, under the tab rule: the raised surface, a rounded border in the rule colour and the text after its tone glyph (`✓`, `!`, `✗`), wrapped at 72 cells and never clipped. Neither takes the focus, and a new notice replaces the current one. The last 50 notices keep their time and their exact raw detail for the F2 `Recent notices` pager, oldest first, each detail indented under its row, wrapped, opened at the newest. Esc on a docked build dialog says what stays waiting and how to reopen it (`No exit chosen. Nothing was filed or landed · F2 Finish reopens it`, `<id> keeps waiting · F2 Answer <id>'s question reopens it`, `Nothing filed. The plan still waits · F10 Plan, then p, reopens it`), cleared early once its subject has an outcome.

Pi's own status, warning and error lines are offered to `statusPresentation` and routed by notice-route.ts, in Chat or away from it. Transient lines are a notice only. A model or effort line is a notice only, because the transcript's model mark already records a change. An error is a notice and also one quiet row in the transcript, so a loss stays on the record. A compaction outcome is a quiet row where the divider would stand and, away from Chat, a notice as well. The sentence drops Pi's or corral's framing prefix, and whatever it leaves out travels as the notice's exact detail and the row's expanded text. With the panels not yet bound or already disposed, or nothing to say past the framing, Pi keeps its own line; its callers and what the model receives are unchanged.

The terminal title leads with what the session needs (`sessionTitle` in chrome.ts): `▲ needs you · <base>`, `● working · <base>` while a turn runs or a fleet child (a build session's, or any other role's) is still live, or the base alone while idle, written only when that state changes, so a herdr tab names the pane that waits. `Bell: off | on` is an F2 setting beside Motion, off by default and session-local; on, each new needs-you episode rings the terminal bell once.

### Transcript
Pi renders the conversation on the background. An owner message opens with `you` in muted and sits on the bubble surface; a message the assistant role tagged with its owner input id loses the `[owner input …]` line and shows the id muted at the right of its first row (its last row when the first is full; nowhere when neither has room). An `ask_user` answer is a `you answered` bubble: the sentence the question asks, muted on one row (the whole question once expanded), then the chosen option in bold and any free text, with no request id. A message another agent sent (a peer message or a child report, agent-message.ts) is that agent's card, not a `you` bubble: a `▍` bar in the sender's colour, `<sender> → parent · message #n` (or `<child> · <state> · report`), six body rows then `… n more rows`, and a report's edited files and usage on a muted foot; a click or Ctrl+O opens it. An owner message over 16 lines or 1600 characters folds to its first 12 rows inside its bubble, with `… n more rows`, and opens the same way. Assistant text is plain. Thinking opens with a bold `thinking` lead and its text is muted, so reasoning never reads as the answer; hidden thinking is one row `thinking hidden · <key> shows it` (Ctrl+T by default). Tool calls are tool rows (below), custom messages fill no band of their own, and build tools draw their own cards (see Build sessions). Consecutive self-framed tool rows sit on adjacent rows, thinking that ends a message with tool calls sits directly above its first tool row, and a row that follows text keeps one blank row above it.

**Markdown.** Code blocks draw no fences: a muted language label row when the fence names one, then the code in the code colour indented two cells, a wrapped line continuing at its own indent plus two. A word wider than the row (a URL, a path) breaks after a `/` or `-` in the last third of the row. Below 50 cells of width a table becomes one block per record, `<header>  <cell>` rows with the header bold and a blank row between records; from 50 cells the grid stays.

**Quiet rows.** What the host or the session adds to the transcript, beyond the owner's words and the agent's reply, is a muted row in the row kit's geometry: the state glyph first (`✓`, `✗`, `!`, `○` neutral, `→` sent or moved, `▲` needs the owner), words clipped at their end, never a key name or the word click. A click or Ctrl+O shows the full text under it (40 rows, then `… n more rows`). Host notices, run marks, failed and stopped turns and the compaction divider follow this rule.

**Chat around the transcript** (chat-overlay.ts). Before the first row, an empty Chat says who receives the message, per role (`Waiting for corral's first instruction. What you send goes to this agent.` for a dispatched role, `Project manager for <project>.`, `Assistant <id>.`, the build session's three sentences), then a muted line `⏎ send   F1 keys   Ctrl+C twice quits` (`/finish ends the build` in a build session). While the reader is scrolled up, Pi's jump control counts what arrived: `↓ 37 new rows · End` (`Ctrl+End` while the draft has text, `↓ Jump to latest message` when nothing arrived); End with an empty draft jumps there.

### Run marks
mark-rows.ts draws the transcript marks (`MARK_ENTRY` custom entries: drawn live and on resume, never in the model's context) as quiet rows under one blank row, the time of day right-aligned. A live interactive rich host records them when it is bound or is a build session (never bound by design); plain UI, a headless attach, startup replay and resume, and an unbound host of any other role record none.

- **Run end**, one per agent run: `✓ done · 3m 12s · 14 tool calls · $0.42 · 120k tokens re-billed  14:35` (`✓ done · 14:35` for a run under 2 s without tool calls); `○ waiting for job j1-4: cargo test + 1 more · the agent resumes when it finishes`; `! the reply was cut at the output limit`; `! auto-continue stopped: <note> · send a message to go on` (a stopped continuation is this one row, with no separate note). A stopped or failed run names no cause here: the stopped-turn or error row right above it does (see Failed and stopped turns), so its run-end row is the neutral `○ run ended · 42s · 3 tool calls · $0.08`. A cost shows only when known.
- **Model**: `○ model → <model> · effort high (was <model> · medium)`, or `○ effort → low (was high)` when only the effort changed.
- **Note**: a host note in its tone (`○`, `!`, `✗`), its first line plus `n more lines`.
- **Child** (build sessions): `▲ <id> asked: …`, `→ <id>: <answer>`, `→ <id> steered: “…”`.

A narrow row drops facts in this order: re-billed tokens, tool calls, time, duration, the resume hint, cost, `+ n more`, `send a message to go on`, the not-run count; the reason clips last. Expanded, the row shows the whole sentence wrapped, every wait and the full text.

### Failed and stopped turns
error-copy.ts words every turn that ended in an error (`presentError`, Pi's `errorPresentation` hook). A failure is one `✗` sentence saying what happened and whether anything was lost (`Nothing was lost.`, `Nothing was sent to the model.`, `The reply above stopped early.`), then one muted next step (`Send a message to retry.`, `It resets at 14:20: wait until then, or choose another model.`), read from the typed provider failure, corral's refusal code or the transport text; an unknown text keeps its own words after `✗`, clipped to 2 rows with `… n more rows`. JSON and raw codes never show collapsed; a click or Ctrl+O opens the full raw text and the failure facts, never cut. A stopped turn is one muted `○` row, never in the error colour, that names who stopped it when the host knows (`StopCause`): `○ stopped by you`, `○ stopped by corral`, or `○ stopped` when the cause is unknown (a stop from before a restart); each may add `· n tool calls did not run` and `· after n automatic retries`. Its pending tool rows read `○ <verb> <target> · not run`. Automatic retrying that gives up reads `✗ Gave up after n automatic retries.`

### Compaction and long sessions
A compaction never clears the transcript, live or on resume: the earlier rows stay readable and the summary box is one divider row, `── context compacted · 483k → 38k tokens · 14:02 ───` across the width (the rule in the line colour, the words muted, shortening to `compacted · 483k → 38k` and `compacted`), with the muted note `Everything above stays readable; the agent keeps only a 120-line summary.` Expanded (a click or Ctrl+O), the note ends `…keeps only the summary below.` and the summary follows, indented. A cancelled or failed compaction is one quiet row where the divider would stand, never a divider: `compaction cancelled · context unchanged`, or `✗ compaction failed · context unchanged` (`automatic compaction failed` for an automatic one, which includes a failed overflow recovery); expanded it holds Pi's exact message and, when another try can help, `Send /compact to try again.` A long session opens on its newest part (about 1,000 rows, starting at a message the owner or host sent) under one row `↑ load earlier · 2,222 earlier messages`, accent then muted; a click draws the next older part and keeps the reader's place. A live transcript over 2,000 rows keeps its newest 1,000 at a compaction and moves the rest behind that row.

### Tool rows
tool-row.ts draws every tool call in one grammar; a presenter (pure, per tool) turns a call into a row model and tool-rendering.ts registers the one renderer resolver in the rich UI. Presenter modules are asked in order (files, commands and jobs, corral, local tools) and a fallback draws any other tool; nested rows (Code Mode children, an agent's conversation) use the same presenters through `presenterFor`. Only the build cards (`task`, `build_finish`, `board_plan`) keep their own renderers, and `codemode` draws a cell (below).

- **The line.** `<state glyph> <verb in accent> <target in text> · <outcome>`, optionally followed by ` · <detail>` (a command's last output line, a first search result), then right-aligned in muted an optional label (`timeout 2m`, a server name, the job id of a backgrounded command), the hidden count and the time, then an optional view label in accent that opens that view on a click.
- **Narrow widths** (`layout`). Glyph, verb and time never drop. The detail shows only while target and outcome fit whole with 8 cells to spare. When the line is too wide, the hidden count, then the right label, then the view label drop. Then an outcome of a third of the row or less (`exit 0`, `no diagnostics`) stays whole and the target takes the rest, at least 4 cells; a longer outcome is capped at 40% of the row and the target keeps at least 12 cells; a target that fits gives the outcome its room back. The verb clips last. A path target clips in the middle (`clipMiddle`): a file name that fits stays whole and the directories give way; a longer name keeps a short head (up to 8 cells, such as a task or run prefix) and the rest of its end, so the extension survives.
- **States.** `writing` (spinner; the time slot reads `writing` while the arguments still stream, and a call whose arguments are incomplete always reads `writing`), `running` (spinner and an elapsed clock), `✓` done, `✗` failed or a definite refusal (outcome `failed` in error by default), `○` waiting, queued, started (a gate), started but not finished here, or `not run` (a call of a stopped turn), `▲` needs the owner (`needs you` in warning), `!` unknown outcome (`outcome unknown` in warning). Final times read `0.4s`, `6.5s`, `12s`, `1m 12s`; a call's own time below 100 ms is hidden, a nested row's reads `40ms`.
- **Body and hidden content.** A successful call is one row. A failed call adds at most 3 muted rows (the reason, or the output tail), indented two cells. Rows never print a key or the word click. What a collapsed row hides is said only as a muted count the outcome does not already state (`11 lines` beside the time, or ` … 41 more lines` ending the last body row); generic nouns such as contents, diff or source are not shown. A click on a row opens or folds that row; Ctrl+O opens or folds every row, and the Chat footer names it (`Ctrl+O expand`, the last composer hint, so it is the first contextual hint a narrow footer drops). Expanded, a row shows its full view (the highlighted file, the rendered diff, the whole output, a corral read's fields).
- **Paths** read relative to the session directory when inside it, else with `~`.
- **Files.** `read <path>:<from>-<to> · 27 lines` (`20 of 300 lines · more`, `image`, `first line too long`); `edit <path> · +2 −2 in 2 hunks`; `write <path> · 40 lines · 1.2 KB`; `grep "<pattern>" in <path> (<glob>) · 35+ matches · 7 files` or `no matches`; `find` and `ls` with counts (`no files`, `empty`). File errors read in words (`not found`, `permission denied`, `is a directory`).
- **Commands and jobs.** `bash <command>` names the command's first line (the session's own `cd` dropped, a heredoc summarised, `(+n lines)` for more); done reads `exit 0` (`exit 0 · no output`), with its last output line as the detail when there is room, a failure `exit 1`, `timed out` or `killed by SIGTERM` with the last 3 output lines. While running, the last two lines of the output tail show under it. A command that moved to the background stays live, `running in the background` with the job id on the right and the `Agents` view label, until the job exits and the row reads its exit; a job this host does not know reads `○ continued in the background`. `job_wait`, `job_output`, `job_kill` and `corral_job_monitor` read `wait`, `output`, `stop` and `watch` and name the command beside the job id (`j1-4 · cargo test`).

- **Local tools** (tool-lines-local.ts). `diagnostics <path> · 2 errors · 1 warning` (`✗` when there are errors, warning tone for warnings only, the first 3 serious items as body rows, `no diagnostics`, `timeout after 30s · <server> still indexing`); `definition` and `references` with `→ path:line` or counts; `fetch`, `web read` and `search` with the site, status, size, byte ranges (`bytes 0-4096 of 9000 · more to read`) or result counts; `browse` and `screenshot` with the page title or the PNG size; `ask` for `ask_user` and `ask_owner` (`▲ waiting for you`, `answered: <choice>`, `no answer: another dialog was open`); `explore` with the prompt's first line, turn and tool counts while they run, then the headline of their findings (`!` and `partial · stopped: time limit` when they stopped early) and the `Agents` view label (`oracle` is still drawn this way in historical transcripts); `tool search`; `MCP connect`, `MCP resources`, `MCP read`, `MCP activate` with counts, and an MCP server's own tool under its registered label with its first argument and the result's line count.

- **Groups** (tool-group.ts). A run of consecutive settled successful rows of one kind (the tool and the row's verb; plan updates across verbs) with nothing visible between them folds into one row in the same grammar, the total time on the right and the newest view label kept. Kinds with a summary of their own fold from 2 rows (`Plan 5/7 · done: … · started: …`, `Attached 5 artifacts · report, 3 logs, screenshot`, `Read T-935 report.md · 4 pages`, `read <path> · 3 reads`, `read ×5 · recovery.rs, evaluate.rs, …`), any other from 3 as `✓ <verb> ×n · <newest outcome>`. A click opens the group; Ctrl+O expand shows every row and collapse folds the groups again. Code Mode cells and build cards never fold.

**Streaming.** Rows redraw as the arguments stream: `write` shows the newest 8 lines of the content it is writing under the row (padded to a fixed height so the row grows once) with the line count and size so far; `edit` shows the end of the text it replaces (`- `) and its growing replacement (`+ `), at most 8 rows, labelled `edit n`; corral prose tools show the newest three wrapped rows of the text being written; a Code Mode cell shows the newest 5 lines of its script. While a call runs, its partial results stream into the row: a managed `bash` the tail of its output, `explore` and `corral_expert` their latest line and turn and tool counts, a Code Mode cell the calls it has made so far.

### Code Mode cells
code-cell.ts draws a `codemode` call as a group: one header row in the tool row grammar and under it the calls the cell actually made, from the runtime's records (`details.cells` while it runs in the foreground, `CodeRuntime.snapshot` and `watch` after it detached), never from parsing the script. Each child is drawn by the same presenter as a direct call of that tool, indented two cells, with its own state, outcome and time.

- **Header.** `code` and its calls with their states (`7 calls ✓5 ⠋2`, `!n` for calls whose outcome went unrecorded, `no tool calls`), the tools it used (`read ×3, bash`, at most three named, from 61 terminal columns), then `✗n` and how the cell ended (`failed`, `timed out`, `cancelled`) in error, and `cell n` on the right from 100 terminal columns. A script that caught a failure reads `✓` with `✗1` in error. A cell with exactly one call is that call's row behind `code ›`. `cancel` and `reset` calls read as one row (`cancel cell 2 · stopped after 3.2s, 4 calls`, `reset kernel · variables discarded`).
- **Fold.** Up to 5 children show. Above that a collapsed cell shows the first 3 and the last ok one, at most 3 running and at most 8 failed children; the rest of each kind fold into one muted row where the first of them stood (`… 12 more ✓`, `… 4 more running`, `… 2 more ✗`). A failed child shows its first reason row. Calls a cell made after it detached or settled read `after the cell`; children of a settled cell the runtime no longer follows read `! outcome not recorded`.
- **Output.** Then `error`, `printed` and `returned`, each under a muted label, 5 rows together while collapsed and `… n more rows` when cut. Printed or returned JSON collapses to one clipped row of its compact form (the call rows above already say what it holds); plain text wraps; expanded, every part wraps in full. The model-facing report text is not drawn.
- **Detached cells.** A cell that keeps running after its call returned reads `in background` on the right, says `the agent continues; this row updates when the cell settles`, watches the runtime and holds the clock, and updates in place until it settles (`settled in background`).
- **Source.** Expanded, every call shows and the script follows under `source`, reformatted by `new Bun.Transpiler({ loader: "js" }).transformSync` (the original text when it does not parse). A collapsed cell names no key and no hidden source; the footer's `Ctrl+O expand` and a click on the cell open it.

Digits, ↑↓ and Enter or a click and a second click choose; Esc changes nothing. A pick asks once (`Rewind to the start of turn 3?`, saying the current work is saved first under a rescue ref, `refs/worktree/corral/rescue/…`), then the host rewinds and a success notice names the ref (`Rewound to the start of turn 3 · current work saved as <ref>`, the host's whole answer in Recent notices). For a conversation-only checkpoint, the option says `conversation only` instead of naming a HEAD. The confirmation says files and Git stay unchanged and there is no rescue ref in the success notice. The host's refusal is a notice in its words. The picker never touches Git or the transcript itself.

### Pager
pager.ts is the one read-only pager: command peek, board task details, agent details, the transcript reader, recent notices, the plan ledger and recorded history. A rounded accent box with the bold title and the muted position (`284–300 / 300`) set into its top border, sized to its content up to 80% of the terminal's rows. ↑↓, PgUp/PgDn (a page less one line), Home/End and the wheel scroll it; q or Esc closes it. Lines clip with `…` so numbered output stays aligned; prose (the transcript, the plan ledger, history, recent notices) wraps, and its position counts wrapped rows. Heading lines are bold in head. `actions` close the pager and return their key (history's `t`, `c`, `n`, `p`); with `raw`, `d` switches in place between the readable lines and the exact records, each keeping its own place and drawn cut at the frame edge with nothing dropped (history recaps, transcript pages and checkpoints). Actions and `d` are key caps in the bottom border and a click on a cap presses its key; an action never shadows `q`, `d` with raw, Esc or a scroll key. Empty, it reads `· no lines` at `0 / 0`. Host events have no pager of their own: they are the Events view.

### Plan review
plan-view.ts draws the submitted plan in a centred accent box, 96% of the terminal width and at most 96% of its height. The top border holds `Plan review · <title>` and the reading position (`§ 3/9 · 41–72 / 214`). The muted facts row reads `revision n · <model> · n sections`, with `since revision n−1: …` from the second submission. The document renders Markdown by section. When there is room, an outline beside it marks the current section with `▌`, changed and added sections with `~` and `+`, and feedback with `✎`. `[` and `]` step sections; a click on the outline goes to that section. `d` shows changes since the preceding submission and `c` marks or unmarks the section for feedback. Reading keys appear as caps in the bottom border.

The choices occupy numbered rows (in a short or narrow terminal, each digit with a short label, wrapped over as many rows as they take). A digit or a click selects and only Enter carries out. The facts row wraps over the rows left above the choices; while the model does not read whole there the hint is `widen the terminal to execute` and no execute choice can be picked, and a choice the overlay cuts off cannot be picked either. Keep planning closes the box and appends marked headings to the composer as quoted lines; the plan stays under review until the owner sends feedback. The box opens when the submitting turn ends, from `/plan` or from its pending row in F10 Plan. Esc leaves the review pending. `m` closes the box, opens Pi's model selector and returns when a model is selected. A model changed elsewhere while the review is open redraws it with that model; executing on a review naming another model redraws instead of approving. The app answers the same submission, and an answer from either side closes the other. `Approved plan · <title>` opens the approved copy read-only, without choices, feedback marks or a model key. A host without panels prints the submitted copy and offers the four choices as a plain selection from `/plan`, or Keep planning alone when the copy cannot be shown.

### History and resume
History (history-model.ts, history.ts, popup-list.ts) is one popup, `History · read-only · n returned · not exhaustive` (`a of n shown` when cut): `Tasks │ Assistants` (Tab), the `›` search, rows with the recorded status as glyph and word (`not recorded` muted when absent), a task's runs in the same popup (`‹ T-001 · Runs`, ← or Esc back), and a failed read in the list with `⏎ retries`. The popup scrolls with `a–b / n` in its border, an entry taller than the window moves by PgUp/PgDn and the wheel before the selection does. The recap pager reads in words and ends `Recorded history · read-only · not an instruction for this session`; `d` shows the exact sources, `t` the transcript pages and `c` the checkpoints (each with `d` for raw records). Nothing there switches, opens, resumes or writes a session. The `/resume` chooser for assistant sessions (resume-list.ts) uses the same popup: rows of id, title, an availability in words (`stopped · resumable`, `current · this pane`, `! open in another pane`, `ended`) and the date; only a stopped row is chosen, the others stay with the reason (disabled, never a grant) and the selected row adds the whole title and the exact record time. Choosing resumes nothing by itself: the host revalidates the pick against fresh state, and the request and its admission are unchanged.

### Read-only main views
F7 Changes, F8 Agents and the other views replace only the main reading area through the optional typed SDK mainView hook; F9 restores the same transcript instance. The real input dock remains SDK-owned. Changes shows a comparison row for a candidate comparison and for any comparison that is not the session's default: `candidate ▾` muted, `<base8> → <head8>` in text, the state in its tone, the scope muted and `updated n ago` on the right; when narrow the time goes first, then the scope, then the state, and the label and both ids always stay. A build session's default worktree comparison and a plain working-tree default show no row. From 90 main columns a 47-cell file column (author chips when the host supplies authors, then one row per file) sits beside the diff, the `│` its own column on every body row; below that the file block stacks above the diff (9, 5 or 3 rows) over a rule that carries `a–b/n` while files lie outside it. A file row is `▌ ●● ! path +a −d`: author dots in hue, `!` and a warning row under it for a flagged file. Untracked files are counted by the store on each refresh (`untrackedStats` in panels-git.ts): regular files only, never through a symlink, at most 256 KiB each, 100 files and 4 MiB per refresh; a file over a limit or unreadable keeps `new`, a binary one reads `bin`. The file whose patch is on screen counts that patch, so while a newer patch waits to be applied its row keeps the displayed counts until `r` applies it. The diff starts with `path ● author` in bold, then hunk rows on the dialog surface in accent (`@@ new file`, `@@ deleted file`, or the hunk line; the current one bold with `i/n` when there are several), added and removed rows on their tints and context rows muted, each with one right-aligned line number (none on removed rows) and its `+`/`−` sign. A comparison without files is one empty-state paragraph. Changes retains scope, selection and captured hunk provenance, exposes meaningful comparison/search/refresh controls, and appends references without submission. Agents distinguishes local job/monitor observations from canonical settlement. Foreground prompts and active selection suppress background interception.

**List and detail sub-views.** Events (from Task, or F2 › Host events in any session), Artifacts (from Proof) and Usage share one layout (panel-parts.ts). Row 0 is a back line, `‹ Task · Events` (`‹ Chat · Events` without a task), `‹ Proof · Artifacts` or `‹ Chat · Usage` with the task and run muted on the right; a click on `‹ <parent>` goes back like Esc. Then one chip row (the state chip `reading…`, `reading… rows kept`, `! read failed` or `! stale · 12:04` in warning, then `! host closed` when the host's session has closed, then the source, gap and count chips, with `read 12:04 (2m ago) · r reread` right-aligned and taking a row of its own before the time shortens), a problem as one clipped `! …` line in plain words with retained rows kept, and one muted caveat line; `?` replaces it with every caveat in full. Lists have a muted header row with aligned columns that drop in a fixed order when narrow, and the `▌` bar (muted while the view does not have the keys); from 105 columns the list sits beside the selected record's detail, below that the detail stacks under it. Details are label and value rows; event JSON is flattened into fields (`gate.stats.passed`), never dumped. Events columns are `# · time · kind`. Artifacts list kind, title and by with `A`/`B` mark chips, in 45% of the width (46 to 60 cells) beside the detail, which shortens the digest to 12 characters with the full SHA256 once on its own row. Enter, or a click on the selected row, opens an artifact: the host writes its exact bytes to a private file (`NativePanelsOptions.artifactFile`), and the view shows them only when they hash to the registered SHA256: UTF-8 text under the fields, an image fitted into the reading area through the image viewer (graphics terminals only; `Image · this terminal cannot draw graphics` otherwise), any other binary content described, never drawn. Usage right-aligns numbers with thousands separators; columns that do not fit move their values to a muted row under each scope, so no number is lost.

**Read states.** One vocabulary for every source the panels read (read-state.ts `ReadState`, worded only in panel-parts.ts: `stateChip`, `stateNote`, `stateBanner`, `stateRow`, `legacyRow`), used by Task, Proof, Events and Artifacts. Phases: `not_applicable` (one neutral `○ Does not apply: …` row stating the reason once; nothing is read and no state chip or note shows), `never_read` (`not read yet`), `loading` (`reading…`), `current` (the read time and age, `reading… rows kept` during a reread), `retained` (rows from the last good read kept, `! stale · 12:04` with the time of that read and, after a failed reread, `Reread failed at 12:06: <reason> · showing data read 12:04`) and `failed` (`! read failed`, the reason, no rows, and what is not inferred). The time of the data on screen survives every shortening. A closed host is a flag beside the state, not a phase; an older record's missing value is `○ <What> not recorded by this <record> · unknown, not zero`, a fact about data, not a phase. Retained data is never relabelled current by a failed or overlapping read.

### Candidate and evidence inspection

Task-bound sessions default Changes to the committed candidate of their run (`base_sha` → `head_sha` from `corral show --json`, the worktree's HEAD before a head is recorded), using exact SHAs for paths, diffstat and hunks. `c` still selects the independent working/index comparisons; `o` is an explicit repository inspection, not a session rebind. Retained diffs keep their captured identities, selected-file status and diffstat until the new patch is explicitly applied.

F10 Proof (task-bound sessions only) and `/panels proof` read the same `corral show --json`: a chip row with the newest gate and review checks in words, then collapsible sections (`Gate result`, `Review findings`, `Task artifacts`), `j/k` and Enter or a click to open one, `a` to the Artifacts view. A check is the engine's result on one commit, never acceptance.

Two different things share the word stale and are never merged: a check on an older commit than the run's head, and the read-state chip of this screen's copy (`! stale · 12:04`: the rows are from an earlier read). Reads coalesce and cache for five seconds, never run from render; a tool outcome invalidates the cache, and only a new read reconciles it. Nothing on these views writes to the engine.

### Usage
Usage (F2 or `/panels usage`; not a tab, its place reads `Chat › Usage`; no function key and no status-bar click) is one **Session** section under its section rule, marked live (usage-model.ts, usage-view.ts): this pane's tokens, API-equivalent USD, context window and model with effort; a build session adds its agents as rows and a `total` row that follows the status bar's cost rule, `+` marking an unknown member; helper usage is neither listed nor summed. There is no spending limit, so no remaining amount is shown. Views under 12 body rows open with a one-row digest, with every fact still below. Reported cost is never a verified bill; API-equivalent USD is neither billed spend nor provider quota; unknown is never zero.

### Images
Click an inline terminal image to fit its existing bytes into the main reading area; the tab row hides while it is open. Click again (including a quick second click), Esc or F9 restores Chat. Draft and transcript instance remain intact. Image placement is bounded by the actual main viewport below the header, not guessed composer height. This uses the optional packaged SDK image activation hook; no fetch, external viewer or model call. Native rendering still requires a supported graphics terminal. Do not layer expanded images in SDK overlays: captions over existing inline graphics are not reliably composited.

Build sessions add data and actions to the same surfaces; every other role renders exactly as above, and shows the fleet views below (child rows, conversations, messages, steering) only once its host reports children or agent messages. An accent card: the header row on the dialog surface holds the question in bold (an agent's name in its hue; a short title below 70 columns) and the policy note muted on the right from 96 columns; an optional body (question text or preview table, `… n more lines`); then numbered options, the number in accent, the label bold in a 26-cell column and the detail muted, one row each from 84 columns and the detail wrapped under the label below (at most three rows; dropped when short). An unavailable option keeps its row with a muted number and label and `unavailable: <reason>` in warning (` · unavailable` when short). ## Do's and Don'ts

- Do preserve the real editor, transcript and bound identity.
- Do show unknown, stale and unavailable state explicitly.
- Do name the scope of every figure; keep session estimates separate from billed spend.
- Do keep presentation hooks inert without panels: plain, bare and headless hosts show stock Pi.
- Do relocate metadata instead of hiding it on narrow terminals.
- Do draw every frame element with the frame.ts primitives on the one background.

- Don't introduce a browser runtime or another agent loop.
- Don't make local UI state look like canonical progress, evidence or authority.
- Don't change native fonts or promise full terminal/accessibility certification.
- Don't fill a band, panel or rail with a surface of its own.

Not canonized: summary ellipsis and small-terminal footer truncation are current limitations, not desired future rules. Low-color terminals and Windows/IME/accessibility have not been comprehensively certified.

## Native integration seam

The `pi-coding-agent` patch in `packages/corral-pi/patches/` adds an optional typed `InteractiveModeOptions.mainView(transcript, presentation)` hook to the pinned SDK's fullscreen layout factory. The original transcript instance is supplied to the host's public-component composition; the original fixed input dock remains outside it, and the workbench adds its dock above the editor through Pi's widget API. The live presentation getter delegates to Pi's existing theme/transformer/tool-renderer methods and supplies its existing TUI, so chat presentation changes carry over without a parallel styling implementation. The assistant renderer accepts presentation-only content/stop/error fields; the inspector does not fabricate model or usage metadata. An optional `readOnlyQueue` mode makes Pi show no queued input of its own and never restore queued input into the owner editor; its `/hotkeys` table reads `Listed and edited by the host, not here`. The rich host enables it and lists queued input in its own queue dock. Defaults are unchanged when these options are absent. The patch is tracked through Bun patchedDependencies/frozen lock. The pi-tui patch supplies removable image activation registration; unregistered images retain stock behavior. No runtime private-field casts, root discovery/reparenting, replacement editor loop or second agent runtime.

Four more optional hooks let the host draw Pi's own surfaces: `dialogPresentation` (the select, confirm and input dialogs), `statusPresentation` (status, warning and error lines), `bashPresentation` (owner `!command` blocks) and `selectorPresentation` (the model, effort, settings and option selectors). Each is handed Pi's data and Pi's own callbacks and returns a component or nothing; Pi keeps the promise, abort signal, countdown timer, dialog stack and every commit path, so no permission call site, option label, default or timeout changes. They are inert when unset. The host passes them only together with the panels; plain UI and headless modes pass none and run stock Pi.

The Terminal adapter supplies default cell colors only in the alternate screen, without OSC palette/default-color setters. Explicit widget/selection colors and opaque clipboard/image protocols are retained. Foreground prompts and active selection suppress background interactions.
