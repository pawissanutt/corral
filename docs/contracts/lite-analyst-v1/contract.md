# Non-Git research session: Corral-next / Lite v1 candidate

**Proposed, disabled.** T-2069 specifies a same-host boundary for offline synthetic conformance against `corral:6`; see the [separate owner decision record](decision.md). No production endpoint, role registration, implementation enablement, private vault, real credentials or live provider use is part of this change. Remote transport, coding handoff and generic research-role configuration are out of scope.

## Authority and launch

- The **Lite host** owns user approval, grant scope, evidence/compute admission, the one foreground turn ledger, and its delivered copy. The **Corral supervisor** owns the session, paid dispatch, local cost and process control, and the original report. UI clients do not relay or possess either authority. Prerequisites for private data include Lite's explicit external-admission/retention decision (including K6/K10/K11), demonstrated local isolation, and separate enablement approval. A run cannot mint publication, broader source scope, or code-task authority.
- A persistent `link_id` identifies one explicit enrollment of the Lite and Corral instances. Authenticate both peers on the private management connection; take link and instance identity from that connection, never from caller-supplied authority claims. Enrollment can be revoked; re-enrollment never reuses the old `link_id`. Binding to the same OS user or knowing a run/handle is not authorization. Neither endpoint accepts Corral owner pairing/session credentials as a substitute. Management messages never enter MCP discovery, model context or a child environment.
- Corral uses a distinct session namespace and private root. Starting requires no project selection, Git probe, worktree, board task, pane or user shell. Claim a durable launch intent before spawn. Serialize the one launch submission with generation/stop/revocation checks in the local supervisor: a fence that wins before submission permanently invalidates that generation's intent. Before crossing the OS boundary record submission-in-progress with a retained launch identity, then attach the child to it (not PID or cwd alone). A fence after submission but before attach must reconcile and stop the submitted child; no `cancelled` or slot release based only on absence of an attached child. Keep the child blocked from tools/provider until current identity and generation's MCP binding are installed. After an uncertain launch, fence and reconcile by retained identity; no resubmission or replacement while the old child may still start or run. v1 may replace a generation only after confirmed teardown and proof of no dispatch/consumption in that run; otherwise reconcile and end it, not resume paid work. Lite must accept a new binding for that generation before returning a permit or disclosing data.
- Existing code is precedent, not an entry point: `crates/corral-daemon/src/ops.rs` is owner operations; `crates/corral-engine/src/artifacts.rs` indexes task/project artifacts; `packages/corral-pi/src/roles/assistant/index.ts` admits files and shell, `host/mcp-settings.ts::serverVisible` gives assistant/build workspace-wide visibility, and `host/mcp-tools.ts` can activate tools dynamically. None is the proposed analyst authority surface. Keep existing defaults unchanged. The host-local automation permit path in `packages/corral-pi/src/host/session.ts` does not establish link, grant, cost, or provider-side idempotence.

## Wire and digest rules

This is the logical message contract, independent of local authenticated framing. All objects are closed (unknown keys, duplicate keys, missing required keys, null unless explicitly allowed: reject); strict UTF-8 JSON, no lone surrogates, no floats, no Unicode normalization. Integers are nonnegative JSON safe integers unless a tool field explicitly permits signed integers. IDs are opaque ASCII `[a-zA-Z0-9_-]{1,64}`. Timestamps are integer UTC epoch milliseconds. Control JSON messages have a 128 KiB encoded cap (including report base64); cut over-limit messages before decoding, with bounded in-flight requests and no unbounded queues. Errors are closed `{error:code}`, with no prose from the peer. Transport correlation IDs and MCP JSON-RPC IDs are not idempotency keys.

- `J(x)` is UTF-8 RFC 8785 canonical JSON; `H(bytes)` is SHA-256, lower-case hex without prefix. Typed preimages have `v:1` and `kind` as below; there is no implicit trimming, newline, concatenation or digest of a base64 string. Base64 uses padded standard RFC 4648 encoding with no whitespace; decode and reject noncanonical encodings.
- Lite writes **exact** canonical start body bytes to its private durable outbox at approval; `request_digest = H(request_bytes)`. Corral decodes, checks canonicality and digest against the raw bytes, and verifies grant binding. Equal decoded values encoded differently are not interchangeable retries. The request body and policy enums have no extensible/free-form properties in v1; negotiate unsupported versions rather than guessing. The digests bind equality, not authentication or anonymization.
- A tool `args_digest = H(J({v:1,kind:"mcp_args",tool,args}))`; stable invocation identity is allocated by the trusted host, not a replayable JSON-RPC `id` or model-supplied metadata. The supervisor passes it out of band through the session binding. A reserve or settle digest similarly hashes its typed body (excluding the digest field). The provider `input_digest` hashes the host's exact finalized outbound model request bytes (body only, never headers/credentials); changing the serialized prompt, tools, evidence or model payload after reservation invalidates dispatch. Lite checks the recorded binding and policy, not the provider bytes themselves.

### Lite → Corral lifecycle

Operation names below are the envelope discriminator; params and successful results are shown without the authenticated envelope. `hello` is mandatory on a new connection: `{versions:[1],profiles:["lite-analyst-v1"]}` → `{v:1,profile:"lite-analyst-v1",corral_instance,policies:[{policy_ref,manifest},...]}`. No common version or profile → `unsupported`, no state created. Advertise only policies allowed for that link (at most 8); Lite recomputes the manifest digest before presenting a choice. The observed model destination is reported by Corral, not independently proved by Lite. The approval UI must show the effective provider/model/recipient (including external use), projected scope/retention and limits before requesting a run.

| Operation | Params | Success / retry semantics |
|---|---|---|
| `start_investigation` | `{request_b64,request_digest}` | Full snapshot. **Unique on `(link_id,request_id)`**, not the digest. Authenticate the link, validate the envelope/body schema and canonical bytes/digest, then look up the key before checking mutable admission. Exact retry returns the current snapshot without acting again, even after deadline; changed valid digest for that key is `conflict` even if the changed question would not have been approved. For a fresh key check approval binding, deadline and budget; in one transaction create the run binding, `admitted` snapshot, concurrency slot and launch intent. An expired unknown request is `expired` and cannot launch. Definitive admission refusal before commit creates no run; the caller may retry the exact still-valid approval, never alter it under the same ID. |
| `read_investigation` | `{run_id}` | Full snapshot; can recover from lost notifications or interrupted mutations. |
| `cancel_investigation` | `{run_id,generation}` | Full snapshot. For active run require current generation; atomically set stop fence, return `stop_requested`, signal supervised stop, and return `cancelled` only on confirmation. Repeat is harmless. If terminal with matching generation, return terminal snapshot, including an already committed report offer; never retract it. |
| `fetch_report` | `{run_id,generation,report_id}` | `{offer,report_b64}` with exact immutable bytes, only for the initiating authenticated link and exact offer; no generic/hash/path lookup. Repeat returns same bytes while retained. |
| `ack_report` | `{run_id,generation,report_id,sha256,bytes}` | `{offer,acked:true}` after exact identity/size/hash match and durable delivery recorded on Lite. Repeat returns the same receipt; no re-import, retention change or endorsement. If removed, neither fetch nor ack can restore the offer. |

Start body: `{v:1,kind:"start_investigation",request_id,grant_id,grant_digest,grant_generation,policy_ref,question,deadline_ms,limits}`. The question is user data, max 4 KiB UTF-8. `grant_digest` commits Lite's immutable approval scope (including vault identity/generation, pinned source/version/field/metric projection, recipient, limits and expiry); Corral carries rather than interprets it. No vault path or note schema crosses the lifecycle boundary. Lite immutably binds `(link_id,request_digest)` in its approval ledger before sending start; Corral first authenticates the enrolling Lite host as approval issuer, then binds grant to `run_id` and generation with Lite via the management channel before work. No independent Corral access to vault state. `limits` is `{calls,response_bytes,total_response_bytes,turns,run_cost_microusd}` with positive call/byte/turn bounds (zero cost allowed only with a proven zero upper bound); supported fixture maxima are 8 calls, 8192 bytes per response, 32768 bytes total, 4 turns and 120 seconds from approval. `deadline_ms` cannot be extended; Lite refuses if it exceeds its approval expiry, Corral refuses admission >120 seconds in the future and computes local stop independently. Clock uncertainty fails closed (see permits). A lower local ceiling can refuse the request; never silently substitute route/scope or raise limits.

Snapshot: `{run_id,generation,seq,state,reason,offer,acked}`; `offer` is null until available (and after owner removal), `acked` is boolean, `reason` is null or a bounded code. `generation` starts at 1, increments only on fenced replacement; `seq` starts at 1 and increases across all visible changes, including across generations and for ack/removal. Clients discard older snapshots, mark offline snapshots last seen, never infer terminal state from silence. States: `admitted → working ↔ waiting_for_source`, nonterminal → `stop_requested → cancelled|failed`, or `working → finished|failed` (admitted/waiting can fail too). Expiry, revocation, scope drift and deadline fence new work; they do not imply the process is gone. If shutdown cannot be confirmed, remain `stop_requested` (no new slot) until reconciled or record a fenced `failed` with quarantine retaining the slot until confirmed. Missing report means failed/partial, never finished. No automatic offline turn. Optional notifications have no correctness role.

Authorize before revealing existence or checking generation. Cross-link and unknown IDs both return `not_found`; an authorized known run with stale cancel/binding generation gives `stale_generation`, and a mismatched or no current report gives `not_found`. A matching report identity with a mismatched ack digest/length gives `conflict`. Other refusal codes include `invalid`, `unsupported`, `expired`, `policy_unavailable`, `budget_exceeded`, `busy`, `unavailable`; Lite admission also uses `stale_scope` and `stopped`. `unavailable` is not proof of no commit. A revoked enrollment cannot read/fetch/ack even if it previously could; remote data already copied cannot be recalled.

## One-use turn reservation and cost

Before any dispatch or evidence call, supervisor-only `bind_session` presents `{request_id,request_digest,run_id,generation,grant_id,grant_generation,policy_ref}` to Lite on the authenticated connection; Lite returns `{bound:true}` only after validating the pinned approval and recording the run mapping. Exact repeat/reconnect is idempotent while active, different run under the same request conflicts, superseded generation is refused. A replacement requires an authenticated supervisor declaration of confirmed prior teardown and no prior consumption plus Lite's own ledger check (no unsettled permit and no prior possible dispatch); on a replacement send the same body with `generation` incremented and `prior_teardown_confirmed:true` (otherwise omit). No child or MCP client can make this declaration. Binding expiry is the pinned request deadline or earlier grant invalidation, never a new deadline on reconnect. Either host can deliver authenticated `fence_session {run_id,generation,reason}` (`reason` is `stopped`, `stale_scope` or `expired`); the current receiver records the fence and returns `{fenced:true}` idempotently, and a stale generation cannot fence its replacement. Signals optimize prompt shutdown, not renewal. A binding authorizes neither model turns nor unmetered MCP calls.

Only the authenticated, bound supervisor may call the following **Corral → Lite** operations, once per provider dispatch (including a retry allowed as a new step after a *resolved* attempt). They are not tools. One outstanding step per run; steps start at 1 and increase without reuse across generations. A `turn_key` is link, run, generation and step. The generation binding maps to the exact request/grant/policy and current peer. Connect/reconnect or renegotiate does not reset turn or tool counters.

1. `reserve_turn` carries `{body,reserve_digest}`; body is `{v:1,kind:"reserve_turn",run_id,generation,step,request_digest,policy_ref,input_digest,max_cost_microusd}`. Corral transactionally holds its worst-case allowance first. Lite checks the bound active run, request, exact policy/recipient, current grant/source/vault/expiry, next step and limits; atomically debit the approved turn count and reserve the upper bound in its existing foreground ledger **before** issue. Return `{permit_id,expires_ms,reserve_digest}`. Same key and digest can retrieve the **same** unexpired outstanding permit, never a fresh one for that step. Changed digest → `conflict`; expired/settled/revoked → refuse. TTL ≤5 seconds, capped by run and grant deadline. Each side uses conservative monotonic remaining time in addition to wall timestamps; deny when clock bounds/liveness are unknown. A lost reserve reply can be recovered only by identical retry while its permit is outstanding and valid. If the permit remains unknown or expired without matching settlement, stop paid work for this run; no newer step and no need to recover the token to close the budget hold. Both sides finalize any still-unresolved issued/held allowance at worst case at `deadline_ms + 300000`, even if the other side never saw the reserve. Only a valid settlement recorded before that horizon can release allowance; the safe disagreement is overcharging a local budget, never authorizing another dispatch.
2. Corral may dispatch only via the trusted provider transport. Immediately at the send boundary require an authenticated live binding, unexpired matching permit, current process/generation, no stop fence, and the held cost. Serialize this admission with local stop/replacement. Durably CAS `held → consumed` for the exact turn/permit/digests before the one send; a consumed permit is **not transferable or dispatchable again** even when the prior response is missing. Disable SDK retries, hedges, implicit model calls (e.g. compaction), and route fallback or reject the route. A crash in the interval between consumption and sending is treated as possibly paid; no attempt to infer whether it reached the provider. Detected revoke/disconnect blocks new dispatch and invalidates unconsumed permits from that connection. Reconnect and bind can reconcile an old permit for bookkeeping but cannot dispatch it or renew its lease. No distributed transaction promises to retract a send racing an unobserved remote revoke or a call already in flight. Bound that window with the short permit; Lite rejects future reservations and MCP releases immediately on local revocation. Cancel/signalled disconnect can stop local processing, not undo a provider disclosure or charge.
3. `settle_turn` carries `{body,settle_digest}`; body is `{v:1,kind:"settle_turn",run_id,generation,step,permit_id,reserve_digest,outcome,charged_microusd}`. Outcomes: `completed` (trusted metered actual), `not_sent` (proof no consumption and no possible send), `indeterminate` (including missing trusted usage or an ambiguous provider timeout). Actual must be within the held upper bound; `not_sent` charges zero, `indeterminate` charges the full bound. A provider reporting overbound is a local policy incident: block further dispatch, record actual separately as overrun, report indeterminate under this contract; stop admitting that route. Corral seals settlement locally before transmission. Lite records at most one settlement of an issued permit, returning `{settle_digest,recorded:true}` on first and identical receipt replay; mismatch → `conflict`. Settlement may reconcile an issued old-generation/expired permit on a still-enrolled authenticated link **only as bookkeeping**, never authorize new work or revive an expired grant. Link revocation blocks even settlement RPC; close local holds at the horizon. A worst-case default on timeout is terminal for budget credit. Before or after that default, record at most one authenticated settlement payload for audit (identical replay returns `recorded:true`); after the default this does not change charges or reopen the run. No next permit until earlier attempts are resolved and Corral has observed Lite's recorded settlement; recover a lost settlement reply with the same payload. A consumed ambiguous turn ends paid work for this run, even if it can be charged or later resolved.

**Corral admission policy.** Default deny unconfigured/revoked links. Owner config pins a revision, allowed exact policy/route refs, max concurrent active or uncertain sessions, max per run and max per fixed UTC day, in integer USD millionths. Admission reserves a concurrency slot; every turn reserves a finite maximum covering the finalized input, capped output and all provider fee classes using a host-pinned tariff/capability revision (round up). Count holds plus actual/indeterminate charges against both run and day caps in one serialized transaction; attach an attempt to the UTC day of its reservation, carry unresolved holds into later-day availability until settled (they are not reset at midnight). Keep the slot through confirmed process stop even after report publication. Lower/revoked policy blocks new reservations and invalidates outstanding unconsumed dispatches; it cannot forgive consumed spend or rebase existing receipts. Provider route must be able to enforce the assumed maxima; unknown/unmetered is not zero. If unsupported, refuse; do not assert a hard currency guarantee for a route that can overrun. Rates and limits come from Corral, not from the model or Lite. Fixture amounts are synthetic, not product defaults.

## Host policy and scoped MCP

A host-resolved policy manifest is `{v:1,kind:"lite_analyst_policy",role:"lite-analyst",prompt_sha256,tool_policy_sha256,route,retention}`; `policy_ref = H(J(manifest))`. `route` is `{provider,model,recipient,external,tariff_revision}`. `retention` is `{transcript:"off",report:"until_owner_removal"}` in this candidate. Prompt digest is over pinned, fully rendered system UTF-8 bytes; resolve trusted installed asset and optional owner customization before advertising the ref. The host always includes the non-overridable role contract (gather evidence, use broker for numbers, cite exact handles, label unknowns, stop at scope), appends only reviewed host customization, and passes question and tool results as data, never system overrides. No client paths, project config, prompt/env interpolation from a vault, or hot reload. Local manifest/prompt/schema/route mismatch on launch or resume fails closed; a change needs a new approval. Model provider auth remains host-side.

`tool_policy_sha256` hashes `J(tool-policy.json)` in this bundle. It pins the model tool names, exact provider-visible descriptions and argument schemas, MCP reply validation schemas, and host-only continuation. An advertised MCP name or annotation cannot replace a descriptor. Before every provider request verify the exact ordered model registry against the pinned descriptors; apply the same allowlist and schema validation at registration, activation, dispatch and any restored state. Pi gets **zero upstream tools** and only `search_materials`, `read_evidence`, `calculate_metric`, `finish_report`. No `read_result`, ask-user, shell/file/Git, code mode, web, board, agents, extensions, skills, arbitrary discovery/resources or general MCP control at the model surface. Do not load assistant/build roles, owner settings, home extensions, tools or project policy and then try to subtract them. No fallback if the provider adapter or Pi host cannot prove this surface.

A trusted per-session stdio shim negotiates MCP `2025-06-18` via `initialize`, sends `notifications/initialized`, and validates `tools/list` against the three evidence descriptors plus host-only `read_result` (not `finish_report`). Wire descriptors consist of the exact pinned name, description and `inputSchema` without annotations or other decoration. `tools/call` results carry validated `structuredContent` per the pinned response schema and empty `content`; do not forward arbitrary text, resource, binary, progress or error data. Other than MCP handshake/list/call, no broker method is consumed. Sort/compare descriptors by name for validation; use the manifest order when constructing the provider registry. Fail on unsupported version, additional model tools, changed descriptors, resource/prompt capabilities, list changes, server-initiated requests, or extra dispatch routes. Only Lite's grant broker can resolve handles. The shim accepts a supervised descriptor or equivalent isolated handoff; never use workspace-wide MCP servers/configuration, arbitrary commands supplied by a peer, argv/env tokens, a vault mount, or the Corral owner socket. Bind the retained channel to authenticated link, run ID, generation, grant generation and policy ref before the first call. The shim's private broker transport wraps each validated MCP `tools/call` JSON-RPC request in `{run_id,generation,invocation_id,args_digest,request}`; the outer identity is supervisor-issued and authenticated by the binding, not part of the model-visible arguments or the Pi-side stdio protocol. The broker recomputes the digest from `request.params.name` and `request.params.arguments`. The reply carries `{run_id,generation,invocation_id,response}`, matched against the outstanding call and its JSON-RPC ID; on an intentional replay only the inner transport correlation ID may change, not the invocation key or digest. Drop unmatched/unauthenticated replies; don't create ledger entries from them. Run from private non-repo scratch, explicit minimal environment and independent OS principals or demonstrably equivalent process and network isolation. Restrict egress to approved broker/provider path; don't assume filesystem permissions protect peers at the same UID. Observe process identity/teardown, actual env/argv/descriptors and egress using synthetic canaries. No private data until proved on target OS.

For each call Lite checks current binding, grant, source/version/vault/route, expiry and scope at admission and again at effect admission or response release. Serialize effect admission and the handoff of the bounded response frame with Lite's local revocation/stale-scope fence; if the fence wins, do not start the effect or release pending fresh/cached evidence. A frame already handed off counts as disclosed, and an already admitted effect may settle locally without releasing a stale result. Read/search only the approved projection; unknown and unapproved handles both `refused`. `read_evidence.start_byte` must land on a UTF-8 boundary of the approved text projection; take up to `max_bytes`, ending at the last included scalar boundary, and refuse empty/out-of-range slices. The citation binds those exact bytes and revision. No path, snippets/statistics from outside the projection, arbitrary SQL/formulas, publication, or writes. `calculate_metric` admits only a predefined metric and approved input combination, may return `pending`; `read_result` polls only an existing same-run operation under the host (no extra model turn). Target broker response <10 s below the existing 15 s client timeout; a timeout/unconfirmed worker is indeterminate, not permission to retry computation. Stop polling by deadline/call cap, and fail or report limitations. If the approved route can't attest a calculation, refuse or label an already captured result, never claim dynamic computation.

Dedup key `(run_id,generation,invocation_id)` and arg digest: before producing a new effect, journal the stable key and exact validated operation. Commit result/provenance and charge before each release; new response envelopes can wrap the exact cached structured reply. Same key/changed digest → `conflict`, never reexecute; uncertain result awaits reconciliation. Same key/same digest returns cached bytes only after current grant/binding checks and charges another disclosure if released again. Each broker call attempt (including replay, polling, errors) debits call allowance, each released structured output (including errors) debits UTF-8 canonical byte count; enforce response and total caps before release. When exhausted, close/refuse at transport without releasing more tool bytes. Host records actual authorized reply receipts and citation handles by run/generation; a calculated handle must identify an attested operation/version/result/cell, not model-authored prose.

## Final report and ownership

`finish_report` takes `{text,citations:[{start_byte,end_byte,handle}]}` (see exact schema). Offsets are UTF-8 byte boundaries into `text`, `[start,end)`, a nonempty claim span. Sort citations by start/end/handle; reject duplicates, invalid spans and handles absent from that generation's actual accepted tool response ledger. Empty citations are allowed for a limitations-only report; no claim that valid handles prove an inference. Host seals `J({v:1,kind:"investigation_report",text,citations})`, ≤65536 bytes including metadata. The attached offer is `{corral_instance,run_id,generation,report_id,sha256,bytes}`; the hash and length describe sealed bytes, not envelope or decoded Markdown. `report_id` allocated by Corral, never a path.

Persist/verify bytes durably first in the private report store, then transact the row, immutable invocation-ledger binding, `finished` transition, offer and sequence increment together. Final report CAS requires a live binding for the active generation, unexpired deadline, `working`, no stop fence and no existing final. Linearize stop/revoke/disconnect observation and finish on the same run row: detected disconnect prevents a new publication until a valid rebind, and a detected revoke permanently fences it. This is a local CAS, not an atomic test of unobserved remote revocation. A stop winner produces no offer even if the blob was written; finish winner preserves its immutable receipt. The host-local success result is `{offer}`. Equal payload digest in that same generation returns the original receipt (even after deadline or disconnect), different digest → `conflict`; a stale generation cannot publish or consume. After owner removal, same-payload replay cannot resurrect bytes. A crash before the row leaves only collectable unpublished bytes; a crash after commit is recovered by `read`/fetch, never creates a second report. Protect staging/current readers from cleanup; treat missing/corrupt committed bytes as unavailable and an operator fault, not an opportunity to regenerate the report.

Corral local owner controls deletion; remote fetch/ack belong only to the initiating enrolled link, not other paired devices via general catalogs. Lite verifies offer identity against its own mapped run/generation, exact size/digest, and its own ledger before durable import keyed by the offer. Render inert text, no executable content, HTML or automatic network fetches. Flag unsupported or unresolved citations. Ack after storing verified bytes and receipt, not after writing authored content. Any authored excerpt later is Lite's explicit reviewed patch with OCC, never part of these APIs.

**Retention.** Show retention separately for Corral, Lite and provider. Corral keeps the original until explicit local owner removal; ack, cancel or reconnect does not delete it. No durable raw Pi transcript in this profile; discard scratch, model context, raw request bytes and non-report evidence working copies once stopped/reconciled. Persist only the report, a bounded receipt ledger (invocation/citation IDs and digests, not the source bodies) while retained, required accounting, and minimal dedup/fence receipts. Lite owns admitted excerpt/result bytes, receipt retention and any imported/user-authored copy. Deletion unpublishes first, then removes private bytes/receipt content (subject to safe reader cleanup); keeps non-plaintext tombstones to prevent reuse. Preserve `(link_id,request_id,request_digest)` and terminal identity for the enrolled link's lifetime; retire with permanently non-reusable enrollment, never reuse run IDs. Quota refusing new starts is preferable to evicting live dedup keys. Accounting holds survive deletion until reconciled and finalized day charges survive their policy window. Digests/metadata remain sensitive; no payloads, secret tokens, tool bytes or unredacted paths in operational logs. Revocation cannot erase previously delivered copies or provider disclosures.
