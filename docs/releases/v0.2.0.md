# corral v0.2.0

[Published October 19, 2026](https://github.com/pawissanutt/corral/releases/tag/v0.2.0)
at 09:37:16 UTC, from tag `v0.2.0` pointing to `967bf45`.
The release contains five native packages, SHA-256 sidecars, packaged asset
manifests and installer-proof JSON. Release preparation was reviewed on
October 17; publication followed separately on October 19.

## Distribution

- Extend the existing Release workflow with pull-request, main/task-branch,
  and manual validation, retaining tag-driven publication behind successful
  validation and native packaging.
- Package native Linux musl x86_64/aarch64, macOS Intel/Apple silicon, and
  Windows x86_64 MSVC executables with license/readme and SHA-256 sidecars.
- Install without Rust using the existing POSIX installer or the new native
  PowerShell installer. Support latest and explicit release tags, custom
  destinations, mirrors, and dry-run target selection.
- Verify archive checksums and probe candidate binaries before replacement.
  Keep the existing executable on download, checksum, archive, version, or
  execution failure.
- Add native installer proof using the actual packaged executables, clean
  user directories, loopback release endpoints, closed stdin, and a PATH
  without Rust.

## Native runtime

Native ports cover process identity/control, hook-child containment and
bounded completion, worktree resident discovery, gate ownership/progress,
resource sampling, file observation, and artifact access. Linux retains its
pidfd-based process identity. Windows uses retained process handles and Job
Objects. macOS 14+ uses PID-version-bound signaling and kqueue exit observation.

Native Windows/macOS runtime validation is not inferred from a Linux build:
the native checks and installer proof must pass before release acceptance.
The Darwin FFI boundary needs native execution; it is not claimed as
Miri-verified.

## Prerequisites and limits

See [installation](../guide/install.md) for exact commands and supported
architectures. Runtime prerequisites remain herdr, Git, and an authenticated
agent CLI. Windows additionally needs Git Bash configured as the engine's
pane shell and used for starting corral.
Read-only planner mode still requires the Linux bubblewrap sandbox and is
unavailable on native Windows/macOS rather than falling back to unrestricted
repository access.

The packages are not Windows Authenticode-signed or macOS-notarized.
Checksums detect corruption/mismatched assets, not independent publisher
identity.

## Publication and evidence

The [published release](https://github.com/pawissanutt/corral/releases/tag/v0.2.0)
provides the native packages, manifests, checksum sidecars and installer proofs.
Verify its publication metadata with:

```sh
gh release view v0.2.0 --json tagName,publishedAt,url,assets
```

Follow the [release runbook](README.md) for future releases. Preserve the
workflow run URL, candidate SHA, native installer-proof JSON, packaged asset
manifests, checksums and full isolated gate log. Fresh native CI and ordinary
gate/review evidence must match the final source; earlier green runs remain
historical evidence. Future publication still requires the owner's explicit
decision.
