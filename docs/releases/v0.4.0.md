# corral v0.4.0

Minor release on top of [v0.3.0](v0.3.0.md). The supported targets and the
corral binary's runtime prerequisites are unchanged. What's new in packaging: the
Linux and macOS archives now also ship `corral-pi-host`, the compiled Pi-native
agent host. See [installation](../guide/install.md).

## Pi-native agent host (opt-in)

- **New harness `pi-native`.** It runs the Pi coding agent under corral's own host
  in a run pane and talks to corral through receipted, idempotent calls instead of
  screen or idle detection. It has worker, reviewer and PM roles, inbox delivery,
  question triage by key and revision, host recovery with `corral agent resume`, and
  usage collection. See the [Pi-native guide](../guide/pi-native.md).
- **Release builds need no Bun.** `corral-pi-host` embeds Bun and every dependency.
  `install.sh` installs it beside `corral` and runs `corral agent install`. Checkout
  builds still install from `packages/corral-pi` on Bun 1.4.2.
- **Subscription logins.** `corral agent login` signs in to OpenAI (ChatGPT
  Plus/Pro) or Anthropic (Claude Pro/Max) using an arrow-key picker, with
  per-provider credentials in corral's own store. Anthropic profiles run through
  the Claude Agent SDK, so usage counts against the plan. They need the `claude`
  CLI on PATH in release builds.
- **Rich run pane.** The pane shows an identity header, corral footer status,
  one-line `corral_*` calls and a Dracula theme. `[agent] ui = "plain"` keeps stock Pi.

## Gates and review

- **Tiered gates.** Quick gates run during review rounds and for Plan members,
  and the full tier runs for main. Receipts are bound to their tier, and
  evidence carries across authorized promotions and clean replays. `corral stats
  --gates` reports per cohort, tier and destination.
- **Reviewer routing.** Routing rules pick the reviewer by task, using versioned
  review contracts. Worker and reviewer conversations are reused across rounds,
  and each new round is named.
- **Review behavior.**
  - Presentation-only objections no longer block a review (contract v3).
  - Landing no longer waits for peer reviews in the same project.
  - Verdicts are recorded against their reviewed base even when main moves.
  - The `max_diff_lines` gate is removed.

## Plans, Autopilot and attention

- **Plan integration targets.** Plans can own integration targets, with
  aggregate verification, final landing and owner acceptance. Owners can add a
  member or amend member gates, and Autopilot can take advisory checkpoints.
- **Autopilot grants.** Grants are confirmed with one key, and project grants can
  cover tasks filed later.
- **Attention handling.** New canonical attention conditions are shown on the
  board, with durable owner-notice accounting, structured task parking and
  `corral attention`.
- **Turbo mode.** A new owner-only mode skips owner acceptance and round limits.

## Delivery, skills and extensions

- **Durable inbox delivery.** A durable inbox core comes with adapters for OmO
  (the thread gateway) and Pi-native (bridge submit_input), plus retained,
  crash-safe retry proof.
- **Role skills.** Versioned corral role skills (worker, planner, submit) are
  refreshed at dispatch and installed once into the shared agents directory.
- **Extension protocol v1.** `corral <name>` forwards to a `corral-ext-<name>`
  found on PATH, and `corral ext run|list` is added.

## Performance and fixes

- **Board and sync.** Board frames do bounded store work with a work budget.
  Session bindings, schema versions and lesson signals are read once per pass.
  Immutable git facts are memoized, and per-sync artifact scans are skipped.
- **Git.** Target status checks no longer take a lock, and a transient
  `index.lock` is retried.
- **Launches.** Agent prompts are delivered by reference, and every agent exit
  is observed with an exit receipt.
- **Analytics and timing.** Cost, token, phase-timeline and throughput analytics
  are added, with monotonic attempt stamps that survive clock steps.

## Publication

Follow the [release runbook](README.md). Pushing the `v0.4.0` tag reruns the
validation and native matrix, builds the compiled host on every Unix runner,
and publishes only after every job passes.
