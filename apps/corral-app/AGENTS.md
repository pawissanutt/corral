# Agent guidance

## Scope

This app lives in the corral repository as `apps/corral-app/`. It is its own Cargo workspace with its own toolchain and is not a member of corral's workspace. Use `bash scripts/app-web-gate.sh` from the repository root for the web packaging check; run the app's Rust tests separately. Design sources are in `docs/app-design/` at the repository root. Read its `README.md` for authority and implementation-status caveats before using `REQUIREMENTS.md`, `ARCHITECTURE.md` and `mockup/`.

The app has three data states (`DataState`):

- **Fixture**: explicitly selected, launch-only sample preview through the same live view-model path; actions affect sample state only. Never restore it on restart or present it as daemon facts.
- **Daemon**: an enrolled native Unix session (`CORRAL_SOCKET`, peer-UID trust and private `0600` device-id file), or a paired browser session over an explicitly enabled numeric-interface WebSocket with pinned Noise IK. Typed reads and engine operations cover all current destinations. Retained/offline snapshots stay visibly stale; capabilities and missing facts remain explicit.
- **Disconnected**: no enrolled/paired data. Never substitute fixture facts. Destinations offer Connect and Preview; Settings remains available, with local preferences in General › This device. Unpaired browsers open Connection.

One trusted owner: a paired browser and the native app have the same authority, and a paired device is the owner. There are no authority classes, previews, proofs or command journals. Every engine operation goes out as `op.submit { op, force }` (`corral_types::Op`); the engine decides every precondition, and a refusal (`refused` error carrying a `corral_types::Refusal`) opens the refusal sheet with one button per typed next step. A forced step reads "… anyway", says what it skips and is its own confirmation. Destructive or forced operations (`drop`, `stop`, `approve`, `retry` with `fresh`, `move` to Done or Dropped, anything forced) ask once on this device before they are sent; everything else runs on one press.

Any attached device or the owner CLI confirms a web pairing by comparing the matching code. Credentials are encrypted in IndexedDB with a non-extractable wrapping key; NSH Storage contains only the non-secret `corral.paired` marker. Revocation stops reconnect; retryable Forget removes local identity/state, not the daemon record. No browser shell executor is enabled. Direct LAN/Tailscale binding is opt-in; remote browsers require operator TLS/WSS (`daemon.web_endpoint`) and an HTTPS origin. There is no embedded TLS or relay.

Ask is one composer for the one chat agent: the PM and the assistant are the same agent, so the composer has one target and no switch (the wire's `target` is always `assistant`). Transaction completion must acknowledge local persistence before send acceptance, matching draft retirement. Per-device/store drafts and cancellable messages survive reconnect; other offline actions refuse. Offline boot may restore complete Tasks/Plans/Projects/Health snapshots only for saved credentials, marked stale; a snapshot from an older wire version is dropped. Revision-checked transactions preserve concurrent instances' updates. Images and bounded UTF-8 files upload from the client; links are opaque. Missing provider/quota/raw-terminal facts stay unknown.

NSH Storage keys: `corral.destination`, `corral.settings`, `corral.theme`, `corral.sidebar`, `corral.pane`, `corral.scope`, `corral.agents.v2`, `corral.paired`. `corral.agents.v2` holds the Agents switcher's pins and the conversation last opened, keyed by authenticated enrollment and daemon store (identity/store → `{ "pinned": ["A-n" | "B-…"], "last": null | "<id>", "docked": ["<session>"], "visible_dock": null | "<session>", "pane_hidden"?: true }`; a record without the dock fields loads with an empty, shown dock), each an exact conversation id, never `quick`; the explicit preview's stay in memory. `corral.scope` holds the one project scope keyed by daemon store (store → `{ "project": null | "<id>" }`), so several daemons can keep separate scopes; it replaces `corral.filters`, which is removed on load. `corral.data`, `corral.conn` and `corral.mode` are removed. Transactional outbox/cache uses IndexedDB `corral-local-state` v1 (`records`, `meta`), or native `corral-app/durable.json` with retained lock. Credentials use IndexedDB `corral-app` v1 (`credentials`) or native `devices.json`. See README › Local storage for record keys, migration and bounds. Cargo version `0.1.0` and NSH package version `1.0.0`/build `1` are diagnostic; negotiate capabilities, not version-string equality.

Projects come from `projects.v1` (`Feed.projects`). A complete empty Projects page is `WorkspaceMode::AssistantOnly`: no project management, board destinations hidden rather than unavailable. Never infer assistant-only from loading, stale or missing-capability state.

The navigation has four places, Home (`h`), Tasks (`t`), Sessions (`s`) and Activity (`a`, with the pages Feed, Timeline, Usage `u`, Artifacts `f` and System `m`), and Settings (`,`) at the sidebar's foot: `Destination` (the nine pages) and `Area` (the places and Settings) in `src/model/nav.rs`. Every task and every session opens one page on every form; a plan (a task with children) and a review candidate (a task in Review) open the task's page. One project scope applies to every place. The former destinations' slugs (`now`, `inbox`, `plans`, `review`, `agents`, `builds`, `changes`), paths and keys (`n`, `p`, `r`) open their new homes. An assistant-only workspace keeps Home (its landing), Sessions, Activity › Usage and Settings. The desktop and terminal sidebar has no Ask entry: `/` opens Ask, and on Home it focuses the composer docked there; the phone keeps its floating Ask button.

Agent sessions keep these rules:

- **One session page for every role.** A task's worker, reviewer or planner run, a chat (`quick`, `A-n`), a build session (`B-…`) and a child agent's conversation (`<session>/child/<id>`) all open the page `model::session::page` builds; a role differs only in the Details sections, dock and actions its host serves. Ask is the same page in compact form (`screens::agents::session::compact`), never a second transcript or composer.
- **The host is the source of truth.** Every fact comes from the host's live state (`SessionState`, `can` included), a served part or the session's row; a fact none of them reports is shown as absent, never guessed or kept locally.
- **Reads go through `ClientRequest::Detail`/`DetailWatch`, actions through `ClientRequest::Session`.** Each part is a `DetailRef` (`SessionCards`, `SessionChild`, `SessionJobs`, `SessionJobOutput`, `SessionChanges`, `SessionChangeFile`, `SessionUsage`, `SessionContext`, `SessionPlan`, `SessionPlanModeDoc`, `SessionEvents`, `SessionModels`, `SessionCommands`, `BuildBoard`, `BuildRecord`) re-read when the host announces `live_part`; each action is a `session.*` or `build.*` request whose reply is read in `feed.operations` under its key. No part module adds another transport.
- **An action the host cannot run stays listed with its reason.** A capability the host declares unavailable, or a host that is not running, mutes the row with why (`ActionRow.unavailable`, `PartBody.unavailable`); the app never hides it or predicts a refusal.
- **A sent message's echo is retired by its input id only**: the transcript holds a message `<session>/input/<command id>`, or the acknowledgement says the host handled it without one. Text and time never match a send to a message.

## How a screen is built

Each domain's model supplies a `State`, reducers and pure view builders. Read the tracked state and environment in a view, render the resulting content with `src/ui/kit/`, and dispatch actions with `AppState::act(signal, reducer)`, which updates the signal and runs returned `Effect`s. Keep wording, numbers and branching in the model. Screens support desktop/web, phone and terminal forms; phone pushed pages use `PhonePage`.
A task or a session shows its one next step as a button and More beside it (`ui/kit/next.rs`); Tasks and Sessions are `list_page`s, whose `Row.cells` match the columns one to one on desktop and terminal.
A terse fact (a count, a tile, a pipeline mark) carries its sentence as a hint (`ui/kit/hint.rs`); the phone has no hover, so a row keeps one explanatory line there.

Give pressable controls and testable regions IDs in these shapes: `task-<id>` and `agent-<id>` (list rows and Home's cards, `list::row_id`; a run is `<task>_<run>`), `project-<id>` (Home's project rows), `section-<key>` (a status or state slug, `needs-you`, `working`), `list-<key>` (`list-home`, `list-tasks`, `list-sessions`), `list-head`, `inspector`, `next-<record id>`, `more-<record id>`, `scope-open`, `scope-open-bar`, `scope-all`, `scope-<project>`, `task-page`, `task-band`, `task-overview`, `task-changes`, `task-history`, `tab-task-<0|1|2>`, `pipeline`, `event-<seq>` (a Feed row), `subnav-<0..4>` (Activity's strip), `node-<kind>-<path>` and `edge-<n>` (the map's cards and edges; `edge-line-<n>` in the tree, the picked node's edges from 0), `crumb-<n>`, `field-system`, `inspector-title`, `home-dashboard`, `home-composer`, `panel-<name>`, `agent-<session>-child-<id>`, `agent-<session>-msg-<seq>`, `job-<id>`, `change-file-<n>`, `hunk-<n>`, `usage-row-<id>`, `session-details`, `details-<section>` (a Details section's header, which folds it), `btn-details-<section>` (its full view), `side-step-<n>`, `side-file-<n>`, `side-agent-<id>`, `side-job-<id>`, `record-<section>`, `dock-<card>`, `queue-<n>`, `opt-<card>-<n>`, `act-<slug>` (a session's action rows), `lane-<id>` (a Timeline lane's button: a task, or `<task>/<run>` when grouped by run), `stat-<key>` (a Home tile), `seg-<group>-<value>` (an operation's choice field: `seg-<field>-<value>`; the branch buttons under Onto: `seg-onto-<branch>`; Configuration's entries `seg-config-<part>-<name>`, switches `seg-config-<key>-<on|off|inherit>` and offered values `seg-config-<key>-<value>`), `field-config-<key>` (a list line `field-config-<key>[<n>]`, the text view `field-config-file`), `btn-<action>` (More's rows: `btn-<operation>` for a task, and for a session `btn-cancel-turn`, `btn-pause`, `btn-resume`, `btn-rewind`, `btn-terminate`, `btn-relaunch`; ## Conventions

- Rust 2024; at most 800 SLOC per file.
- No `unwrap()`, `expect()` or `panic!` outside tests; no `todo!()`.
- No dead or commented-out code. Comments say why, not what.
- Route UI, UX and visual work to the `ui` agent.

## Shared host and toolchain

Run only one cargo or NSH build at a time. Never generate load. Never build the `desktop` feature or the Linux or GPUI targets on this host; GTK 4 development packages are unavailable. Do not run `cargo run`, `nsh run` without `--target`, or `nsh run --target linux` or `gpui` here. The available targets are headless, `tui` and `web`.

`rust-toolchain.toml` pins rustc 1.97.1 and `wasm32-unknown-unknown`; NSH 0.6.1 needs rustc 1.97. Keep the pin and `.cargo/config.toml`, which disables the crashing global sccache wrapper and points the wasm compiler tools at the host's clang 18 installation.

If another process holds `~/.cargo/.package-cache`, builds can use `CARGO_HOME` pointing to a directory with `registry`, `git`, `bin` and `config.toml` symlinked from `~/.cargo`, together with `CARGO_NET_OFFLINE=true`.

## Walking the terminal UI

`scripts/tui-walk.py` starts `nsh run --target tui --port <port>` (default 8797) in a pseudo-terminal of `--size COLSxROWS` (default 140x44), runs steps given as arguments or in a `--steps` file, and prints the screen as text. It uses `pyte` from `/tmp/corral-tui-walk-venv`, created on first use; it writes nothing else outside `/tmp`. It counts as the one NSH build at a time. It draws as the owner's terminal does: it drops an inherited `NO_COLOR` (agent shells set it, and NSH then draws reverse video and bold alone), sets `COLORTERM=truecolor` and `NSH_TUI_COLORS` from `--colors` (`truecolor`, `256`, `16`, `mono`), and answers NSH's OSC 10/11 colour queries with `--background` (default dark `1e1e1e`; `none` leaves them unanswered, so NSH draws no surfaces). The app restores the last destination, and on Artifacts the filter keeps the keys, so start a walk with `fixture key:ctrl+k type:Home key:enter` rather than a place's letter.

Steps: `fixture` (Ctrl+K, `Data: fixture`, Enter: the explicit sample preview), `key:NAME[*N]` (`enter tab stab esc up down left right home end pgup pgdn bs del space`, `ctrl+x`, `alt+x` or one character, such as `R` for Shift+R), `type:TEXT`, `wait:TEXT`, `gone:TEXT`, `sleep:SECS`, `screen`, `rows:A-B`, `attrs[:all]` (reverse, bold, underline and background runs; `all` adds foreground colour) and `diff` (the styled runs that changed since the last `attrs`/`diff`). With colours the keyboard focus is the terminal's blue band and a selection a grey one; at every depth a focused kit control (button, segment, tab, list or sidebar row) leads with `›` in its first Cell, where a selected row shows `▌`. While a menu, sheet, form, the palette, a confirmation or the full-size artifact is open, the key line gives that surface's keys. Example: `scripts/tui-walk.py fixture key:ctrl+k type:Home key:enter key:t key:j key:enter screen` (Home, then Tasks, the next row, its page).

Against a real daemon the driver passes its environment through: run it with `CORRAL_SOCKET=<root>/.corral-next/daemon.sock` (from `corrald-next --root <root> run`), `XDG_STATE_HOME=<scratch>` (where enrolment writes `corral-app/devices.json` and `durable.json`) and `XDG_DATA_HOME=<scratch>` (where NSH Storage writes `com.example.corral/storage.json`; without it a walk changes the owner's saved destination and settings section). The first launch shows "not enrolled": open Settings › Connection and press Enrol; later launches with the same `XDG_STATE_HOME` reattach. `nsh run` rebuilds when a source file is saved and its build output lands in the same pseudo-terminal, so stray characters on screen after an edit are the build's, not the app's; restart the walk after editing.
