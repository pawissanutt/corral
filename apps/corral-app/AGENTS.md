# Agent guidance

## Scope

This app lives in the corral repository as `apps/corral-app/`. It is its own Cargo workspace with its own toolchain and is not a member of corral's workspace; corral's gate does not build or test it. Design sources are in `docs/app-design/` at the repository root. Read its `README.md` for authority and implementation-status caveats before using `REQUIREMENTS.md`, `ARCHITECTURE.md` and `mockup/`.

The app has three data states (`DataState`):

- **Fixture**: explicitly selected, launch-only sample preview through the same live view-model path; actions affect sample state only. Never restore it on restart or present it as daemon facts.
- **Daemon**: an enrolled native Unix session (`CORRAL_SOCKET`, peer-UID trust and private `0600` device-id file), or a paired browser session over an explicitly enabled numeric-interface WebSocket with pinned Noise IK. Typed reads and engine operations cover all current destinations. Retained/offline snapshots stay visibly stale; capabilities and missing facts remain explicit.
- **Disconnected**: no enrolled/paired data. Never substitute fixture facts. Destinations offer Connect and Preview; Settings remains available, with local preferences in General › This device. Unpaired browsers open Connection.

One trusted owner: a paired browser and the native app have the same authority, and a paired device is the owner. There are no authority classes, previews, proofs or command journals. Every engine operation goes out as `op.submit { op, force }` (`corral_types::Op`); the engine decides every precondition, and a refusal (`refused` error carrying a `corral_types::Refusal`) opens the refusal sheet with one button per typed next step. A forced step reads "… anyway", says what it skips and is its own confirmation. Destructive or forced operations (`drop`, `stop`, `approve`, `retry` with `fresh`, `move` to Done or Dropped, anything forced) ask once on this device before they are sent; everything else runs on one press.

Any attached device or the owner CLI confirms a web pairing by comparing the matching code. Credentials are encrypted in IndexedDB with a non-extractable wrapping key; NSH Storage contains only the non-secret `corral.paired` marker. Revocation stops reconnect; retryable Forget removes local identity/state, not the daemon record. No browser shell executor is enabled. Direct LAN/Tailscale binding is opt-in; remote browsers require operator TLS/WSS (`daemon.web_endpoint`) and an HTTPS origin. There is no embedded TLS or relay.

Ask is one composer for the one chat agent: the PM and the assistant are the same agent, so the composer has one target and no switch (the wire's `target` is always `assistant`). Transaction completion must acknowledge local persistence before send acceptance, matching draft retirement. Per-device/store drafts and cancellable messages survive reconnect; other offline actions refuse. Offline boot may restore complete Tasks/Plans/Projects/Health snapshots only for saved credentials, marked stale; a snapshot from an older wire version is dropped. Revision-checked transactions preserve concurrent instances' updates. Images and bounded UTF-8 files upload from the client; links are opaque. Missing provider/quota/raw-terminal facts stay unknown.

NSH Storage keys: `corral.destination`, `corral.settings`, `corral.theme`, `corral.sidebar`, `corral.filters`, `corral.paired`. `corral.filters` holds each screen's project filter and Now grouping keyed by daemon store, so several daemons can keep separate scopes. `corral.data`, `corral.conn` and `corral.mode` are removed. Transactional outbox/cache uses IndexedDB `corral-local-state` v1 (`records`, `meta`), or native `corral-app/durable.json` with retained lock. Credentials use IndexedDB `corral-app` v1 (`credentials`) or native `devices.json`. See README › Local storage for record keys, migration and bounds. Cargo version `0.1.0` and NSH package version `1.0.0`/build `1` are diagnostic; negotiate capabilities, not version-string equality.

Projects come from `projects.v1` (`Feed.projects`). A complete empty Projects page is `WorkspaceMode::AssistantOnly`: no project management, board destinations hidden rather than unavailable. Never infer assistant-only from loading, stale or missing-capability state.

Destinations are Now, Changes, Plans, Agents, Review, Timeline, Usage, Artifacts (key `f`) and Settings. Inbox merged into Now (its first group, Needs you) and Builds into Agents; the old `inbox` and `builds` slugs and the `i` key open their new homes.

Agent sessions keep these rules:

- **One session page for every role.** A task's worker, reviewer or planner run, a chat (`quick`, `A-n`), a build session (`B-…`) and a child agent's conversation (`<session>/child/<id>`) all open the page `model::session::page` builds; a role differs only in the tabs, dock and actions its host serves. Ask is the same page in compact form (`screens::agents::session::compact`), never a second transcript or composer.
- **The host is the source of truth.** Every fact comes from the host's live state (`SessionState`, `can` included), a served part or the session's row; a fact none of them reports is shown as absent, never guessed or kept locally.
- **Reads go through `ClientRequest::Detail`/`DetailWatch`, actions through `ClientRequest::Session`.** Each part is a `DetailRef` (`SessionCards`, `SessionChild`, `SessionJobs`, `SessionJobOutput`, `SessionChanges`, `SessionChangeFile`, `SessionUsage`, `SessionContext`, `SessionPlan`, `SessionEvents`, `SessionModels`, `SessionCommands`, `BuildBoard`, `BuildRecord`) re-read when the host announces `live_part`; each action is a `session.*` or `build.*` request whose reply is read in `feed.operations` under its key. No part module adds another transport.
- **An action the host cannot run stays listed with its reason.** A capability the host declares unavailable, or a host that is not running, mutes the row with why (`ActionRow.unavailable`, `PartBody.unavailable`); the app never hides it or predicts a refusal.
- **A sent message's echo is retired by its input id only**: the transcript holds a message `<session>/input/<command id>`, or the acknowledgement says the host handled it without one. Text and time never match a send to a message.

## How a screen is built

Each domain's model supplies a `State`, reducers and pure view builders. Read the tracked state and environment in a view, render the resulting content with `src/ui/kit/`, and dispatch actions with `AppState::act(signal, reducer)`, which updates the signal and runs returned `Effect`s. Keep wording, numbers and branching in the model. Screens support desktop/web, phone and terminal forms; phone pushed pages use `PhonePage`.
A count is a `glance::Stat` (icon and number alone, sentence as hint); a row's explanation is its hint, with one explanatory line kept on phone.

Run only one cargo or NSH build at a time. Never generate load. Never build the `desktop` feature or the Linux or GPUI targets on this host; GTK 4 development packages are unavailable. ## Walking the terminal UI

`scripts/tui-walk.py` starts `nsh run --target tui --port <port>` (default 8797) in a pseudo-terminal of `--size COLSxROWS` (default 140x44), runs steps given as arguments or in a `--steps` file, and prints the screen as text. It uses `pyte` from `/tmp/corral-tui-walk-venv`, created on first use; it writes nothing else outside `/tmp`. It counts as the one NSH build at a time. It draws as the owner's terminal does: it drops an inherited `NO_COLOR` (agent shells set it, and NSH then draws reverse video and bold alone), sets `COLORTERM=truecolor` and `NSH_TUI_COLORS` from `--colors` (`truecolor`, `256`, `16`, `mono`), and answers NSH's OSC 10/11 colour queries with `--background` (default dark `1e1e1e`; `none` leaves them unanswered, so NSH draws no surfaces). The app restores the last destination, and on Artifacts the filter keeps the keys, so start a walk with `fixture key:ctrl+k type:Now key:enter` rather than a destination letter.

Steps: `fixture` (Ctrl+K, `Data: fixture`, Enter: the explicit sample preview), `key:NAME[*N]` (`enter tab stab esc up down left right home end pgup pgdn bs del space`, `ctrl+x`, `alt+x` or one character, such as `R` for Shift+R), `type:TEXT`, `wait:TEXT`, `gone:TEXT`, `sleep:SECS`, `screen`, `rows:A-B`, `attrs[:all]` (reverse, bold, underline and background runs; `all` adds foreground colour) and `diff` (the styled runs that changed since the last `attrs`/`diff`). With colours the keyboard focus is the terminal's blue band and a selection a grey one; at every depth a focused kit control (button, segment, tab, list or sidebar row) leads with `›` in its first Cell, where a selected row shows `▌`. While a menu, sheet, form, the palette, a confirmation or the full-size artifact is open, the key line gives that surface's keys. Example: `scripts/tui-walk.py fixture key:ctrl+k type:Now key:enter key:R "type:Keep it paused" key:enter screen`.

Against a real daemon the driver passes its environment through: run it with `CORRAL_SOCKET=<root>/.corral-next/daemon.sock` (from `corrald-next --root <root> run`), `XDG_STATE_HOME=<scratch>` (where enrolment writes `corral-app/devices.json` and `durable.json`) and `XDG_DATA_HOME=<scratch>` (where NSH Storage writes `com.example.corral/storage.json`; without it a walk changes the owner's saved destination and settings section). The first launch shows "not enrolled": open Settings › Connection and press Enrol; later launches with the same `XDG_STATE_HOME` reattach. `nsh run` rebuilds when a source file is saved and its build output lands in the same pseudo-terminal, so stray characters on screen after an edit are the build's, not the app's; restart the walk after editing.
