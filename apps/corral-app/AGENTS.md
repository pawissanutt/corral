# Agent guidance

## Scope

This app lives in the corral repository as `apps/corral-app/`. It is its own Cargo workspace with its own toolchain and is not a member of corral's workspace; corral's gate does not build or test it. Design sources are in `docs/app-design/` at the repository root. Read its `README.md` for authority and implementation-status caveats before using `REQUIREMENTS.md`, `ARCHITECTURE.md` and `mockup/`.

The app has three data states (`DataState`):

- **Fixture**: explicitly selected, launch-only sample preview through the same live view-model path; actions affect sample state only. Never restore it on restart or present it as daemon facts.
- **Daemon**: an enrolled native Unix session (`CORRAL_SOCKET`, peer-UID trust and private `0600` device-id file), or a paired browser session over an explicitly enabled numeric-interface WebSocket with pinned Noise IK. Typed reads and engine operations cover all current destinations. Retained/offline snapshots stay visibly stale; capabilities and missing facts remain explicit.
- **Disconnected**: no enrolled/paired data. Never substitute fixture facts. Destinations offer Connect and Preview; Settings remains available, with local preferences in General › This device. Unpaired browsers open Connection.

One trusted owner: a paired browser and the native app have the same authority, and a paired device is the owner. There are no authority classes, previews, proofs or command journals. Every engine operation goes out as `op.submit { op, force }` (`corral_types::Op`); the engine decides every precondition, and a refusal (`refused` error carrying a `corral_types::Refusal`) opens the refusal sheet with one button per typed next step. A forced step reads "… anyway", says what it skips and is its own confirmation. Destructive or forced operations (`drop`, `stop`, `approve`, `retry` with `fresh`, `move` to Done or Dropped, anything forced) ask once on this device before they are sent; everything else runs on one press.

Any attached device or the owner CLI confirms a web pairing by comparing the matching code. Credentials are encrypted in IndexedDB with a non-extractable wrapping key; NSH Storage contains only the non-secret `corral.paired` marker. Revocation stops reconnect; retryable Forget removes local identity/state, not the daemon record. No browser shell executor is enabled. Direct LAN/Tailscale binding is opt-in; remote browsers require operator TLS/WSS (`daemon.web_endpoint`) and an HTTPS origin. There is no embedded TLS or relay.

Ask is one composer for the one chat agent: the PM and the assistant are the same agent, so the composer has one target and no switch (the wire's `target` is always `assistant`). Transaction completion must acknowledge local persistence before send acceptance, matching draft retirement. Per-device/store drafts and cancellable messages survive reconnect; other offline actions refuse. Offline boot may restore complete Tasks/Plans/Projects/Health snapshots only for saved credentials, marked stale; a snapshot from an older wire version is dropped. Revision-checked transactions preserve concurrent instances' updates. Images and bounded UTF-8 files upload from the client; links are opaque. Missing provider/quota/raw-terminal facts stay unknown.

NSH Storage keys: `corral.destination`, `corral.settings`, `corral.theme`, `corral.sidebar`, `corral.filters`, `corral.paired`. `corral.filters` holds each screen's project filter and Now grouping keyed by daemon store, so several daemons can keep separate scopes. `corral.data`, `corral.conn` and `corral.mode` are removed. Transactional outbox/cache uses IndexedDB `corral-local-state` v1 (`records`, `meta`), or native `corral-app/durable.json` with retained lock. Credentials use IndexedDB `corral-app` v1 (`credentials`) or native `devices.json`. See README › Local storage for record keys, migration and bounds. Cargo version `0.1.0` and NSH package version `1.0.0`/build `1` are diagnostic; negotiate capabilities, not version-string equality.

Projects come from `projects.v1` (`Feed.projects`). A complete empty Projects page is `WorkspaceMode::AssistantOnly`: no project management, board destinations hidden rather than unavailable. Never infer assistant-only from loading, stale or missing-capability state.

Destinations are Now, Changes, Plans, Agents, Review, Timeline, Usage and Settings. Inbox merged into Now (its first group, Needs you) and Builds into Agents; the old `inbox` and `builds` slugs and the `i` key open their new homes.

## Module map

- `src/lib.rs`: root `App`.
- `src/model/`: pure Rust, with no `nsh_*` imports or I/O; holds data, wording, state, reducers and view builders for every form.
- `src/model/daemon.rs`, `daemon_board.rs`: owned daemon feed and its pure updates. Rows hold the served `corral_types` values (`TaskRow`, `PlanRow`, `AgentRow` keyed `<task>_<run>`, `UsageSummary`, `SettingsSnapshot`, `Event`); `daemon_board.rs` derives Now's groups and the run/gate/review/land rail from task rows. `Operation.refusal` keeps a refused `op.submit`'s typed refusal.
- `src/model/act.rs`: `Act` (an engine operation, `force`, and whether it already was confirmed), which operations ask first, what force skips, the operation's status, and the refusal sheet's buttons.
- `src/model/session_feed.rs`: a watched session's open turn, its child-agent fleet (`session.fleet.v1`, replaced per page) and continued transcript items, with their pure updates; `src/model/agents/` holds the live-run roster and panel, the chat input (`live_reply.rs`, which sends `reply`), the children and agent-message lists (`fleet.rs`) and the transcript replay (`replay*.rs`, `items.rs`).
- `src/client/`: shared frame/session core, native Unix adapter and device-id persistence, browser WebSocket/Noise adapter and encrypted IndexedDB credentials, wire-to-model mapping, and root-owned tasks updating the daemon feed.
- `src/client/{durable,durable_native,durable_web}.rs`: acknowledged revision-checked storage; `outbox.rs`: per-namespace drafts/messages/tombstones; `offline.rs`: credential-checked stale bootstrap snapshots.
- `src/client/app/{local,devices,scopes,terminal}.rs`: local persistence lifecycle, device operations, scoped subscriptions and terminal windows; `src/client/requests.rs`: UI intents, including `submit` (`op.submit`), `config_get`/`config_put` and `pane_focus`/`pane_keys`; `src/client/web/{identity,lifecycle,keystore,push,push_runtime}.rs`: browser identity, Forget, storage and opt-in Web Push/service-worker bridge.
- `src/model/hue.rs`, `text.rs`, `effect.rs`: semantic colours, rich text, environment and reducer effects.
- `src/model/glance.rs`: counts, loop bands, named stage rails and activity strips, each with its hint.
- `src/model/nav.rs`, `health.rs`, `commands.rs`: navigation, health and palette commands (the palette lists the selected task's Actions menu); `NavState.opened` and `opens` track records opened by name so narrow Plans and Review show the record; `src/model/preview.rs`, `preview/`: the explicit sample workspace and a small local engine (`engine.rs`) that applies, refuses with typed next steps, and records operations as the daemon would; never a client executor.
- `src/model/disconnected.rs`: honest empty shell snapshot, without sample facts.
- `src/model/commands/keys.rs`: focused-list bindings and shared terminal legends; `src/model/settings/{qr,config,connect,push}.rs`: pairing QR, the read-only `corral.toml` view, first-run instructions and push preferences.
- `src/model/board/`: shared board vocabulary and task lines.
- `src/model/work/`, `plans/`, `timeline/`, `agents/`, `usage/`, `review/`, `settings/`, `assistant/`: domain reducers and view logic; `work` covers Now and Changes. `work/verbs.rs` is the one Actions menu (all 15 engine operations in the plan's order, always enabled), `verb_forms.rs` the input each operation asks for, prefilled from the task, `verb_context.rs` the served choices a form offers (profiles with the engine's resolved default, projects, the effective base), and `verb_build.rs` turns it into an `Op` (a dispatch leaves untouched defaults to the engine). `work/closed.rs` models the paged done/dropped list via `DetailRef::Closed`; `work/task_page.rs` builds the off-board task view from `TaskDetail`. Sample preview uses the same live reducers/routes/screens, not separate per-screen fixture behavior.
- `src/model/work/now_digest.rs`: since-visit digest; `now_keys.rs`: list walk; `now_page.rs`: Now page, rows, the running slots readout, where Now opens (`opens_at`, the first task that needs you) and side panel; `live_task.rs`: the selected task's story, including a Blocked card's reason, detail, reply box (`ReplyBox`, `Press::Answer`) and next-step buttons, and each dependency's served status.
- `src/model/agents/roster.rs`: scoped session roster (`.` opens the selected run's Session menu); `roster_panel.rs`: selected-session panel and its summary; `menu.rs`: a run's Session menu (the controls that apply, then Reply, Focus pane where it can work, then its task's Actions menu, `work::Record::Session`); `control.rs`: the controls (Cancel turn, Pause, Resume, Terminate, Relaunch, Rewind…), each a `session.<control>` request whose reply is read under its request id (a refusal opens the refusal sheet with corrald's reason). A worker offers Pause or Resume as its run row's `paused` flag says (a daemon that does not report it gets both); a reviewer is never paused or rewound; a lost host is relaunched rather than terminated; a chat's row state picks its controls. Terminate asks once on this device. Rewind… opens the rewind sheet, and a turn picked there asks once on this device. A pending question is named by the session row's `question_id` and drawn from the transcript's newest `corral_owner_question` snapshot of it (`prompt.rs`), answered in place through `prompt.answer`. `pane.rs`: the keys bar and type field (`Effect::Pane`, `pane.keys`/`pane.focus` under their own request id, outcome kept per session). ## How a screen is built

Each domain's model supplies a `State`, reducers and pure view builders. Read the tracked state and environment in a view, render the resulting content with `src/ui/kit/`, and dispatch actions with `AppState::act(signal, reducer)`, which updates the signal and runs returned `Effect`s. Keep wording, numbers and branching in the model. Screens support desktop/web, phone and terminal forms; phone pushed pages use `PhonePage`.
A count is a `glance::Stat` (icon and number alone, sentence as hint); a row's explanation is its hint, with one explanatory line kept on phone.

Give pressable controls and testable regions IDs in these shapes: `task-<id>`, `plan-<id>`, `project-<id>`, `agent-<id>` (a run is `<task>_<run>`; including Project page session rows), `agent-<session>-child-<id>`, `agent-<session>-msg-<seq>`, `thread-<id>`, `lane-<id>` (a Timeline lane's button: a task, or `<task>/<run>` when grouped by run), `stat-<key>`, `loop-<key>`, `seg-<group>-<value>` (project filters: `seg-project-<all|unassigned|id>`; an operation's choice field: `seg-<field>-<value>`; the branch buttons under Onto: `seg-onto-<branch>`), `btn-<action>` (the Actions menu: `btn-<operation>`; the Session menu's trigger `btn-session-menu` and its controls `btn-cancel-turn`, `btn-pause`, `btn-resume`, `btn-rewind`, `btn-terminate`, `btn-relaunch`; the rewind sheet's turns `btn-rewind-turn-<n>`; a Blocked card's steps `btn-next-<n>`; the refusal sheet's `btn-refusal-<n>`), `opt-<n>`, and `page-title`. Preserve the shell IDs `tab-<slug>`, `nav-<slug>`, `settings-<slug>`, `ask-open`, `ask-close`, `health`, `health-source` and `count-<slug>`.

The explicit preview offers Demo controls; normal palette entries use the served data. List keys bind only with list focus or no focused control, never over overlays or sheets; Tab and Space are not list bindings. The app never predicts a refusal: every engine operation stays enabled. Keep the sidebar available/collapsible, auto-folding when narrow. Render real dates, not mockup dates. Review defaults to Unified below about 1100 pt of content width.

## Conventions

- Rust 2024; at most 800 SLOC per file.
- No `unwrap()`, `expect()` or `panic!` outside tests; no `todo!()`.
- No dead or commented-out code. Comments say why, not what.
- Route UI, UX and visual work to the `ui` agent.

## Shared host and toolchain

Run only one cargo or NSH build at a time. Never generate load. Never build the `desktop` feature or the Linux or GPUI targets on this host; GTK 4 development packages are unavailable. Do not run `cargo run`, `nsh run` without `--target`, or `nsh run --target linux` or `gpui` here. The available targets are headless, `tui` and `web`.

`rust-toolchain.toml` pins rustc 1.97.1 and `wasm32-unknown-unknown`; NSH 0.5.1 needs rustc 1.97. Keep the pin and `.cargo/config.toml`, which disables the crashing global sccache wrapper and points the wasm compiler tools at the host's clang 18 installation.

If another process holds `~/.cargo/.package-cache`, builds can use `CARGO_HOME` pointing to a directory with `registry`, `git`, `bin` and `config.toml` symlinked from `~/.cargo`, together with `CARGO_NET_OFFLINE=true`.

## NSH API

Use the [NSH documentation index](https://nsh.dev/llms.txt); documentation pages are available as `.md`. The NSH 0.5.1 crate sources are under `~/.cargo/registry/src/*/nsh-*-0.5.1/`. Read the relevant documentation and source or a real call before using an API.

## Walking the terminal UI

`scripts/tui-walk.py` starts `nsh run --target tui --port <port>` (default 8797) in a pseudo-terminal of `--size COLSxROWS` (default 140x44), runs steps given as arguments or in a `--steps` file, and prints the screen as text. It uses `pyte` from `/tmp/corral-tui-walk-venv`, created on first use; it writes nothing else outside `/tmp`. It counts as the one NSH build at a time.

Steps: `fixture` (Ctrl+K, `Data: fixture`, Enter: the explicit sample preview), `key:NAME[*N]` (`enter tab stab esc up down left right home end pgup pgdn bs del space`, `ctrl+x`, `alt+x` or one character, such as `R` for Shift+R), `type:TEXT`, `wait:TEXT`, `gone:TEXT`, `sleep:SECS`, `screen`, `rows:A-B`, `attrs[:all]` (reverse, bold, underline and background runs; `all` adds foreground colour) and `diff` (the styled runs that changed since the last `attrs`/`diff`). On this target the keyboard focus is reverse video with underline and a selected row is reverse video alone, so `key:tab diff` shows where each Tab lands. Example: `scripts/tui-walk.py fixture key:n key:R diff "type:Keep it paused" key:enter screen`.

## Tests

Keep tests few and name each for the defect it catches. Test at the lowest layer that can fail. Do not pin wording, styles or incidental layout.
